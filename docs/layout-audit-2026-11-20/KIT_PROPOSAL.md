# Kit feedback: текст вокруг интерактивного поля

**Статус: предложение по QA, без изменения kit/runtime.** Реальный потребитель — Seeds Bits, PR #8; исходный дефект и версии: [аудит](README.md). Использованный guidance — `eba8f9d655c4f55eb1b02f9022456d3bf941b979`, `docs/layout/STABLE_PROGRESS_UI.md`. Установленные runtime pins не обновлялись.

В существующей методике уже есть проверка начальной видимости и hit-test действий. Этот случай предлагает дополнить её пятью сценариями:

1. Измерять один и тот же контейнер практики до ответа, после ответа и на следующем шаге; пустая сетка после ответа не должна подменять якорь измерения. Резервировать финальную подпись продолжения до раскрытия кнопки.
2. Проверять центр каждой видимой занятой клетки под плавающим/контекстным UI сразу, через несколько секунд и после перехода. «Подсказка видна» и «переход работает» не доказывают доступность соседних клеток.
3. На границе прокрутки учитывать округление WebView и достижимость цели. Не оставлять кнопку навигации, которая уже не может приблизить цифру.
4. При ошибке сохранения проверять одну полную строку игрового поля, один видимый источник ошибки и доступный повтор. Длинная причина прокручивается без вытеснения игры.
5. Отдельно проверять локальные текстовые колонки и настоящий Android font_scale. Отсутствие horizontal overflow у документа и CSS-имитация увеличенного текста не заменяют эти проверки.

Параметры зон, тексты, 9 колонок, порог 1 px и конкретная политика подсказки остаются в Seeds. Общего runtime-механизма здесь не извлечено. Следующий шаг для kit — рассмотреть эти проверки как дополнение документации; перенос DOM/CSS игры целиком не предлагается.
