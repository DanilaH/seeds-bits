### Что в основном цикле уже работает и сохранено

- Обычная пара имеет локальную обратную связь; состояние фиксируется перед ожиданием декоративной анимации. Полный выигрыш и крупные награды выразительнее выбора цифры. Не стали добавлять постоянный шум или конфетти на каждый ход.
- Семечки летят из удалённых клеток к банке. Победное празднование ждёт успешного сохранения; оформление не начисляет награду само.
- Банка — накопление между партиями. Страница — ближайшее завершение шести задач. Тетрадь — более длинный маршрут. Медаль — отметки решённых дней месяца; серия — последовательность реальных дней. Это разные масштабы, новая валюта им не нужна.
- Маленькие первые задачи и большие поздние поля уже используют один набор правил. Различие раскладок подтверждается проверкой набора, но это не доказательство интересности всех 2400 задач.
- Возврат в незавершённую тетрадь, дата архивного дейлика, самостоятельная отмена, повтор той же подсказки без нового списания и отказ от рекламы без награды уже предусмотрены.
- Звук выключен по умолчанию, вибрация включена, пользовательские настройки сохраняются. Наличие разных сигналов проверяется кодом/harness; физические ощущения и баланс громкости дистанционно не оценены. Без доказательств дефекта настройки не переворачиваем.

### Оставшиеся продуктовые вопросы

Первая самостоятельная победа в классике может оказаться далёкой; новый короткий маршрут только снижает стоимость выбора. Не установлено, какая доля новичков его заметит. Перегруженность 100 тетрадями, интересность поздних полей и восприятие рекламного предложения требуют наблюдений игроков. Ограниченность данных не оправдывает скрытое упрощение, перестановку цифр или давление на rewarded.

## Контракт аналитики schema 2

| Событие | Фактический смысл |
|---|---|
| `game_open` | Вход в игровой контекст: `resume` при boot, `switch`, `restart`. **Не SDK-сессия.** Добавлены `attempt`, `task`, `in_progress`. |
| `game_start` | Первое игровое действие вне урока в данной попытке, включая выбор клетки/вызов подсказки. **Не первая корректная пара.** Теперь отправляется после сохранения. Старый смысл сохранён. |
| `game_complete` | Переход конкретной попытки в завершённое состояние, подтверждённое сохранением. Содержит `attempt`, `task`, moves, hints. Повтор задачи — другая попытка. |
| `tutorial_start/end` | Однократный первый урок и исход `complete/skip`; записываются с флагами. Не счётчик всех открытий справки. |
| `first_pair` | Первая принятая пара вне урока; `assisted` — совпадала ли с ранее показанной подсказкой этой позиции. |
| `first_unassisted_pair` | Первая принятая пара, которую не показывала подсказка в этой позиции. Это операционное определение, не чтение мыслей игрока. |
| `first_hint`, `first_no_moves`, `first_complete` | Первое показанное решение, первое достигнутое затруднение после хода, первое сохранённое завершение. Флаги однократны на сохранение/установку. |
| `hint_used` | Показ новой подсказки, не sticky-повтор; фактическое использование интерфейса, не подтверждение durable завершения. |
| `hint_offer` | Открытие добровольного предложения видео при исчерпании бесплатного/общего запаса. Не preload и не просмотр. |
| `hint_reward_granted`, `daily_reward` | Награда попала в сохранённый wallet. Receipt повторно не начисляет; событие также журналируется. |
| `save_error/recovered` | Переход в состояние ошибки записи и успешный повтор. Ограниченные stage/reason/conflict; без сырых ошибок и содержимого поля. Не доказывает потерю данных. |
| `ad_request/loaded/load_error` | Жизненный цикл загрузки SDK. Баннер может обновляться; числа не являются последовательной воронкой намерений. |
| `ad_shown/impression/clicked/closed/reward_earned` | Callback соответствующего формата. `reward_earned` — receipt SDK, `hint_reward_granted` — отдельно сохранённая выдача игры. |
| `reminder_*`, `review_*` | Запрос/результат permission, пользовательский toggle/открытие; подготовка/завершение review flow. Завершение flow не доказывает оценку в сторе. |

Общий native контекст: `schema:2`, `build_channel:release|preview`, `app_version`, `app_build`, `ads_test`. Старый `test` сохранён как синоним **ad mode**; он не определяет QA-трафик. `APPMETRICA_API_KEY` используется для release. `APPMETRICA_QA_API_KEY` — необязательный отдельный счётчик preview; без него preview-аналитика выключена. Новые постоянные идентификаторы устройства/пользователя не добавлены. JS-события содержат `launch` — случайную метку жизни WebView, и `occurred_at` — время самого действия. Отложенный журнал сохраняет исходные значения после перезапуска. Native ad callbacks используют штатное время/session SDK; собственной JS-метки запуска у них нет.

При медленном мосте ожидающие snapshot объединяются в последний успешно сохранённый, а не накапливаются для каждого хода. Журнал ограничен 128 событиями; native кэширует 512 последних принятых IDs. Обычные ad callbacks не пишутся в game save. При длительной недоступности моста старейшая необязательная телеметрия вытесняется: прогресс важнее полноты аналитики. Подтверждение bridge означает локальную постановку в SDK. Между SDK enqueue и записью native receipt остаётся crash gap: возможен повтор с тем же `event_id`. В выгрузке schema 2 нужно дедуплицировать по `event_id`, попытки — по `attempt`; exactly-once приём сервером не обещается. Сбой телеметрии не блокирует игру.

Для первой попытки/первого запуска связывать schema 2 milestones по `attempt`/`launch`, фильтровать build/version/channel. `launch` не равен SDK-сессии: фон/возврат может открыть новую SDK-сессию в той же WebView. Для SDK-retention использовать штатный `session_id` в Logs API. При отложенной доставке время события SDK относится к постановке в SDK, поэтому время прохождения брать из `occurred_at`; учитывать, что часы устройства могут быть неверны. Отдельно анализировать первый запуск и возвращения. Не делить агрегаты `game_complete/game_start` и не трактовать `game_open` как DAU или sessions. Новые установки без прежнего прогресса/пройденного обучения сохраняют `cohort:fresh-v2`, прежние сохранения — `legacy`. Это когорта сохранения, не постоянный ID человека. Первые события новой schema у legacy-пользователя означают первое **наблюдаемое** действие после обновления, а не первое действие в его жизни; такие события исключаются из воронки первого опыта. Старые события без ID остаются отдельным legacy-периодом. Старые завершённые попытки задним числом не синтезируются.

Primary references: [Android SDK events](https://appmetrica.yandex.com/docs/en/sdk/android/analytics/android-operations), [Logs API events](https://appmetrica.yandex.com/docs/en/mobile-api/logs/ref/events). Реальное соответствие счётчика выгрузке нужно подтвердить в кабинете по package/version/build; здесь доступа к нему нет.

## Сохранения и независимые проверки

Wire v5 / meta v2 и фундаментальные правила сохранены; analytics — дополнительное ограниченное optional поле. Старые сейвы читаются без придуманной статистики. Новая версия не должна сбрасывать boards, history, done, hints, wallet, jars и серии. Старые сборки могут не поддерживать новые измерения; downgrade не объявляется поддерживаемой миграцией.

Проверяем отдельными fault injections: ошибка записи именно завершающего хода; успешный повтор; reload после отказа записи; успешная запись при недоступном analytics bridge; восстановление того же event ID после reload; повтор reward receipt до/после успешной записи; сбой native ack; прерывание/обновление приложения с прежним payload; переключения и конфликт вкладок. Existing tests дополняются, а не считаются доказательством отсутствия дефектов.

Транзакционная граница Android — SharedPreferences commit game+settings. Reward receipt хранится отдельно до grant, ack следует после сохранения. При реальном отказе диска и последующем убийстве процесса последние несохранённые действия сохранить гарантированно невозможно; UI предупреждает и предлагает повтор. Ранее durable прогресс должен остаться пригоден к восстановлению. Браузерный reload проверяет этот контракт, но не симулирует все варианты обесточивания файловой системы Android.
