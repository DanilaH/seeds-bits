# Banner shelf in both orientations · 23 October 2026

The Android game now reserves a bottom banner shelf in portrait and landscape, including short portrait screens previously excluded by the 600 CSS pixel height threshold. Menus, tutorial and full-screen ads still hide the native banner. The shelf does not move when an ad fills or fails.

The initial shelf estimate is 72 CSS pixels in portrait and 60 in landscape, plus a 16 pixel separation allowance and the system bottom inset. The native SDK reports its calculated banner height through a `bannerSize` event before loading. CSS reserves that height; if the initial shelf is too short, the bridge waits for the resized placement instead of silently discarding the banner. Rotation resets the native size calculation. This changes size during placement negotiation, before the banner request, rather than when the network fills the ad.

The game and empty shelf share the same paper background in both themes, removing the contrasting green outer-background strip. Low landscape screens put the jar in the same header row as navigation, leaving room for controls and the banner. The bottom system inset is accounted for by the shelf instead of being duplicated inside the game area.

## Verification

The added browser matrix checks seven sizes, both themes, nonzero insets on every side, a minimum 8 pixel gap below controls, reachable hint/undo buttons, matching empty backgrounds and no horizontal page overflow. It also tests a larger SDK height report, a smaller report after rotation, and hide/show on menu transitions. Banner placement screenshots contain a clearly labelled test rectangle, not a real ad impression.

Three additional native harness cases check that a 90 pixel SDK banner is not requested inside a 72 pixel shelf, loads after the shelf grows, and reports a different height after rotation. These use deterministic SDK doubles; a real SDK compile and Android release acceptance are separate checks.
