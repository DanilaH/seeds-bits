## Implementation

- Enable release R8 with `proguard-android-optimize.txt` and resource shrinking in the reproducible Android configuration script.
- Retain JavaScript bridge methods and runtime annotations. Respect consumer rules bundled by Capacitor and SDK AARs; do not blanket-keep SDK packages or suppress missing-class errors globally.
- Encode the two large Android icon/splash assets as lossless WebP. Decoded RGB pixels match their PNG sources exactly. Store PNG and legacy launcher images are unchanged.
- Upload R8 mapping, merged configuration, usage, seeds and resource reports for every release. The report archive is retained separately from the user APK for crash analysis.
- The APK verifier resolves renamed annotation types using the actual R8 mapping and checks their presence on the bridge, public bridge methods, SDK entry points, native images, production configuration, signature and permissions.

## Verification

Android 35 acceptance: 11/11, offline. Includes native bridge initialization (monetized hint counter), spending three credits, unavailable rewarded video returning without granting credits, saved balance and board after process restart, undo, rotation, privacy and offline startup. No accessibility acquisition retries were needed.

Native Java bridge: 16 deterministic scenarios passed on unchanged production Java sources. Configuration tests cover repeated setup, live-only production configuration and enabled R8/resource shrinking.

An initial browser run passed all 94 standard cases and 14/15 extra cases. R07 reloaded immediately after undo, before the queued storage transaction committed: UI showed 36 cells while the last durable snapshot correctly still had 34. Its expectation incorrectly assumed the undo had already committed and treated a hint on the different restored board as a repeat. The revised test accepts only the two coherent transaction boundaries and checks credit cost against the restored board; R13 separately requires confirmed undo persistence and a free repeated hint. No runtime save or hint logic was changed, and retries were not added to hide the failure.

Follow-up run 39780603958: successful. 45 unit tests, 2 model scenarios, 15 extra + 94 standard browser scenarios, 16 native bridge scenarios; web, Yandex draft and Android debug builds passed. Release run 39779672559 also passed all jobs.

The first verifier attempt incorrectly assumed that annotation class names could not be obfuscated. Mapping confirms `PluginMethod` → `com.getcapacitor.k0` and `CapacitorPlugin` → `k1.b`; the corrected verification checks the mapped types rather than disabling the assertion.
