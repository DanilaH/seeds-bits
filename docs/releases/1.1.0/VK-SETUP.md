# Подготовка VK Рекламы — 1.1.0

Код игры подготовлен. Рекламный кабинет, трекер и постбеки в этой работе не настраивались и контрольная рекламная установка не выполнена. Кампания и бюджет не запускались. Yandex Ads остаётся монетизатором внутри игры.

## Что уже в APK

- Стабильный package `com.seedsbits.game`, AppMetrica Android SDK 8.6.0 с существующим ключом. В 8.2.0 появилась поддержка получения RuStore install referrer; в 8.6.0 исправлен связанный ANR. Второй MMP или отдельный SDK VK ради этого не добавлены.
- События `game_start`, `game_complete`, `tutorial_start`, `tutorial_end`, `first_pair`, `first_no_moves`, `hint_used`, `hint_offer`, `hint_reward_granted`, `daily_reward`, `reminder_*`, `review_*`. Учебные пары не считаются `first_pair`. Уровень/режим и исход обучения помогают отличить реальную игру от открытия приложения.
- Денежный Ad Revenue отправляется вручную из ILRD Yandex SDK для banner/interstitial/rewarded в AppMetrica. Используются исходные `revenue`, `currency`, ad unit, сеть и precision. Нет расчёта денег по количеству показов; пропущенные/невалидные данные и тестовые объявления не создают финансовое событие из кода игры. Это не подтверждение уже пришедшего денежного отчёта.
- Поля, сохранения, звёзды и тексты отзывов не отправляются в пользовательские события. Напоминание локальное и не требует push-токена.

## Действия в кабинетах

1. Добавить опубликованную RuStore-карточку в VK Рекламу и проверить package id. Использовать реальный идентификатор приложения из кабинета; не выдумывать его и не подставлять ключ AppMetrica вместо VK app id.
2. В AppMetrica создать/выбрать трекер партнёра VK Реклама. Целевая ссылка — нужная RuStore-карточка. Получить из интерфейса трекинг-ссылку и настройки партнёрских постбеков; использовать текущие предлагаемые макросы VK, не собирать случайную UTM-ссылку вместо MMP-трекинга.
3. Проверить передачу установки и выбранных целевых событий в VK. Начать с достаточно частого полезного действия: `first_pair` или `game_start`; `game_complete` использовать для анализа качества и лишь при достаточном объёме — для оптимизации. `tutorial_end` оценивать с параметром `outcome`, поскольку skip не равен завершению обучения. Покупок в игре нет — события purchase не создавать.
4. Не отправлять редкие технические ошибки, попытку оценки или системное разрешение как выдуманную ценную конверсию. Отдельно выбрать окно атрибуции и зафиксировать его в отчёте кампании.
5. Контрольный путь на чистой установке: настоящая тестовая рекламная/трекерная ссылка → RuStore → установка → первый запуск → первая пара → событие в AppMetrica → источник/кампания → подтверждённый постбек в VK. Открытие уже установленной игры не доказывает install attribution.
6. Отдельно подтвердить ILRD: реальные показы без кликов по собственным объявлениям → число/валюта/precision Ad Revenue → отчёт AppMetrica. Не оценивать окупаемость по одним `ad_impression` или `ad_shown`.
7. Сравнивать платные/органические когорты и тестовые устройства отдельно; расходы, возвраты и Ad Revenue брать за одинаковый горизонт. При нынешней малой аудитории рост сам по себе не доказывает влияние обновления, пуша или кампании.

Ключи и токены хранить в кабинетах/секретах, не в APK/публичном репозитории и не в чате. Уже существующие четыре GitHub-переменные не переименованы.
