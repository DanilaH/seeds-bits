# UI composition review · 23 October 2026

The home screen now uses the available screen instead of a narrow centered dialog. This pass implements all eight composition changes agreed with the user.

## Result

1. Startup home is a full screen with no misleading close button. Pause retains an explicit return to the current game. Escape returns through nested screens; startup home remains a destination.
2. Home uses two columns on wide screens, one column on phones, and utility navigation at the bottom. A compact composition keeps controls reachable at 568×320.
3. Current classic game has one primary action. The separate classic shortcut appears only when another mode is current.
4. Short boards no longer begin below a large top spacer. Feedback sits near the board. Landscape puts the board beside its header and controls; phones retain bottom controls.
5. Notebook continuation appears before filters and volume selection. Tablets show two columns of pages. Empty filters, replay, selection and navigation retain their existing behavior.
6. Progress leads with the actual jar, percentage and remaining amount, followed by reachable notebook continuation and secondary statistics. Empty jar inventory offers a route to classic play.
7. Theme, sound and vibration use binary switches with native checkbox state and switch semantics.
8. Stronger type hierarchy, consistent quiet surfaces and separators distinguish primary actions without adding decorative artwork or marketing copy.

## Scope limits

This is a composition pass, not a claim that every release concern has disappeared. The earlier independent audit remains at [docs/audit-2026-10-23/REPORT.md](../audit-2026-10-23/REPORT.md): cross-tab preference conflicts, malformed imported daily dates and the synthetic audio saturation case are outside this UI change. Live ad delivery, AppMetrica dashboard receipt and physical-device feel require their separate production checks. The Android acceptance run is offline and exercises unavailable-ad recovery without real impressions.
