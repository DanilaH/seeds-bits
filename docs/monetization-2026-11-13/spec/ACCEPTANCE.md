# Приёмка: Семечки, монетизация и помощь

Нормативные требования — в `TASK.md`. Здесь фиксируются наблюдаемый результат и доказательство. Отмечать **PASS / FAIL / BLOCKED / NOT RUN**, с версией сборки и средой. Не превращать BLOCKED из-за отсутствия телефона в PASS по браузерному mock.

## 1. Основная очередь A и общий контракт C1

| № | Сценарий | Ожидаемый результат |
|---|---|---|
| A-01 | 0 подсказок, найден совет, ready, видео earned | +3 выданы один раз; исходная пара раскрыта после закрытия рекламы; один расход, 2 остаются; второго tap нет |
| A-02 | Обычное поле после pause/resume рекламы не изменилось | `cancelHint()` не делает intent автоматически stale; выполняется A-01 |
| A-03 | Два listener callback, receipt в show result, затем reload | Одна выдача, не более одного расхода, стабильный результат конкретного intent |
| A-04 | Процесс убит после native earned, до JS | После запуска receipt восстановлен и выдан один раз; награда не пропадает |
| A-05 | Процесс убит после grant, до применения | +3 сохранены либо восстанавливается уже зафиксированная подсказка без второго расхода |
| A-06 | Durable save выдачи не прошёл | Receipt не подтверждён и не затёрт новым показом; после retry награда выдана один раз |
| A-07 | Сохранение расхода/эффекта не прошло | Нет подтверждения успешного расхода и потери заработанного; reload восстанавливает согласованное состояние |
| A-08 | Native acknowledge не прошёл | Повторное чтение receipt не выдаёт награду повторно; повтор acknowledge безопасен |
| A-09 | Во время ожидания изменились попытка, режим или board | Весь earned pack остаётся в запасе; новая позиция не подсвечивается/не меняется |
| A-10 | Видео закрыто без earned, unavailable, ошибка show | Ни выдачи, ни списания; доступны выход и обычные действия |
| A-11 | Старый pending receipt найден при неудачном новом запросе | Выдаётся его исходный продукт; UI не объявляет новое видео успешно пройденным |
| A-12 | Старая запись `{token,attempt}` после обновления | Только +3 hints; ни Магнита, ни plan-charge |
| A-13 | Receipt с неизвестной версией/product | Нет догадки о награде, нет ложного acknowledge; диагностируемое сохранённое состояние |
| A-14 | Повтор уже оплаченной пары, в том числе после Undo | Дополнительный credit не расходуется |
| A-15 | Classic без пар; Notebook/Daily unknown/dead | Нет продажи несуществующего совета; бесплатный Add или существующее восстановление доступны |
| A-16 | Загрузка ещё идёт; игрок закрыл оффер; пришёл loaded | Нет автопоказа, повторного открытия и списаний |
| A-17 | Ready потеряно между tap и show | Корректное завершение запроса с причиной; UI не зависает |
| A-18 | Pending receipt/background/занятый fullscreen | Не запускается параллельный показ, не затирается заработанное |
| A-19 | Кнопка при нуле в варианте A3 | Для нового платного раскрытия видны видео/+3; повтор уже оплаченной пары остаётся обычной бесплатной подсказкой |
| A-20 | Узкий portrait, landscape, крупный шрифт | Предложение, награда, CTA и выход читаемы; нет перекрытия системными областями |

Проверки A-03–A-13 должны включать настоящий сериализатор и restore; native-специфические пункты — targeted bridge/Android verification, а не только TS mock.

## 2. Магнит B1

| № | Сценарий | Ожидаемый результат |
|---|---|---|
| M-01 | Fixture из пакета | До эффекта нет обычных пар; `[3,14]` = 6+4 обычным правилом запрещена; после Магнита `[4,15]`, затем `[2,16]` очищают поле |
| M-02 | Выбрана числово несовместимая/пустая/одинаковая ячейка | Нет разрешённого эффекта, оффера или расхода |

| M-05 | Числово допустимая пара есть, полезность не доказана | Нет обещания «спасения», нет дебита; на поле с прежними ходами witness использует действительно открытую Магнитом пару |
| M-06 | Лимит поиска исчерпан | `unknown`; интерфейс отзывчив; нет сообщения «решения нет» |

| M-08 | Демонстрация → новая попытка/reload/update/Undo | Демо не выдаётся заново; usage-limit и assisted сохраняют правильную семантику |
| M-09 | Есть заряд; подтверждён валидный preview | Ровно один расход и один эффект; обычные правила глобально не ослаблены |
| M-10 | Нет заряда; earned; intent валиден | +1 заряд и однократное применение обещанного эффекта; второй callback не повторяет действие |
| M-11 | Earned, но поле сменилось | Один заряд остаётся в запасе; никакое другое поле не меняется |
| M-12 | После применения нажать Undo | Исходное поле/scroll/игровые счётчики вернулись; inventory/использованный лимит не отмотались |
| M-13 | Вернуться на точное исходное поле и повторить тот же Магнит | Разрешён бесплатный replay по entitlement; нельзя бесплатно выбрать другую пару |
| M-14 | Undo → другая ветка → reload → точный возврат | Entitlement не превращается в новый charge и не исчезает; replay доступен лишь на доказанном состоянии той же попытки |
| M-15 | Второй новый Магнит в одной попытке | Недоступен по лимиту v1; просмотр ради неиспользуемого заряда не навязывается |
| M-16 | Магнит → обычная пара → Undo/replay циклы | Сам Магнит не меняет moves/highWater и не выдаёт семечки; ordinary pair credit не фармится повторно; assist-счётчик отделён |
| M-17 | Победа после Магнита, обычных hints не было | Победа assisted; Undo не превращает её в unassisted; старые банки не теряются |
| M-18 | Старый незавершённый Classic после обновления | Восстановлен без подмены правил; новые силы появляются только в новой подходящей попытке |
| M-19 | Offline с уже заработанным зарядом | Проверенный эффект работает без рекламы/интернета; pending telemetry не блокирует игру |
| M-20 | Отключён флаг новых офферов | Заряды/receipt не удалены; допустимое использование ранее заработанного сохраняется либо при опасном дефекте явно отложено |

Дополнительно: набор минимум 12 позиций с размерами, proof, временем/бюджетом и отрицательными случаями. Отдельно профиль на доступном физическом Android; 1800 логических клеток — проверяемый guard, не обещание FPS.

## 4. Общие данные и измерение C2/C3/C4

| № | Сценарий | Ожидаемый результат |
|---|---|---|
| D-01 | Сохранения форматов 2–5 | Прогресс, банки, wallet, история и настройки сохраняются; новые поля имеют безопасные defaults |

| D-03 | Разные продукты одновременно в очередях/восстановлении | Продукт закреплён receipt; hints не превращаются в Магнит/план |

| D-06 | Одно событие повторно доставлено | Downstream dedup по стабильному ID, нет двойных grant/consume milestones |
| D-07 | ILRD отсутствует/повреждён/тестовый | Нет выдуманного нуля или live-дохода; coverage/status явно отличимы |
| D-08 | В кабинете есть и automatic events, и manual AdRevenue | В отчёте один канонический денежный поток; одинаковый показ не сложен дважды |
| D-09 | Перезапуск/new attempt/смена режима; ни одного оффера | Assignment установки не меняется и попадает в экспорт без exposure; eligibility задана до различий вариантов; проверен join с денежным источником |
| D-10 | QA/preview/test ads | Исключены из коммерческой когорты по явным полям |
| D-11 | R7 и D7 в отчёте | У всех включённых установок одинаковое зрелое окно; D7 [168,192) не объявлен готовым на 7-е сутки |
| D-12 | Мало данных/неполные деньги | Отчёт говорит об ограничении; нет фиктивного статистического победителя |
| D-13 | Выключить новый продукт | Его заработанные права сохраняются; никакого разрушительного downgrade save |

Физическая доставка SDK → кабинет/экспорт проверяется отдельно. Сравнение вывода mock-событий с ожидаемым JSON не подтверждает её.

## 5. Поздние выключенные варианты

**A4.** Только явный переход «Короткая задача» после сохранённого результата добавлен в вариант policy. Интервал interstitial остаётся 180 секунд, rewarded обновляет общий guard, незагруженное объявление не задерживает игру. Поздний fill не прерывает новую задачу. Tutorial, nav, restart, Add/Undo и resume не дают новые показы.

**B3.** Три отдельные задачи имеют валидные solutions в пределах 2 Add. Остановка только при непустом поле, нуле пар и нуле оставшихся Add. Undo/restart бесплатны. Rewarded-бонус +1 привязан к версии продукта и не дублируется через Undo/process death. Прототип не меняет реальные Classic/Notebook/Daily saves. Mock-реклама явно обозначена.

**B4.** Multiset/количество цифр строго сохранены; width9; пустоты уплотнены по правилу; результат имеет обещанный witness. Preview детерминирован, отказ ничего не меняет, Undo возвращает точные пустоты/scroll, unknown ничего не расходует. Прототип выключен для аудитории.

## 6. Комплект доказательств реализации

В отчёте реализации приложить:

1. Фактическую ветку/commit, включённые флаги, версии правил/save/receipt.
2. Результаты существующих build/tests и целевых сценариев выше, без заявления о пройденных непрогнанных случаях.
3. Короткое видео A1 и B1, включая Undo и перезапуск, с названием устройства/среды.
4. JSON fixtures с expected outcomes и воспроизводимый запуск, замеры поиска по размерам.
5. Sample событий от native до локальной очереди; отдельно фактическое подтверждение кабинета, если доступно.
6. Статусы по блокам: код / тестовая сборка / audience pilot / коммерчески подтверждено.

Если доступен только browser/emulator, основную доступную работу завершить и выдать сборку/результат с точным списком непроверенных телефонных пунктов. Не застревать на попытке получить недоступную внешнюю проверку и не подменять её синтетикой.
