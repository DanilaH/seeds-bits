# Семечки: монетизация и новая помощь

**Пакет ТЗ v1 · 13 ноября 2026 · для репозитория `DanilaH/seeds-bits`.**

Здесь объединены два обсуждения: улучшение уже существующих подсказок и рекламы; глубокие изменения помощи и механики. Это спецификация будущей работы, а не отчёт о реализованных функциях или доказанном росте дохода.

## Что открыть

1. **`SEEDS_BRIEF.pdf`** — короткая визуальная карта для владельца игры.
2. **`TASK.md`** — единственная нормативная спецификация. При расхождении с обзором действует она.
3. **`ACCEPTANCE.md`** — проверяемые сценарии приёмки по тем же ID требований.
4. **`SOURCES.md`** — фактическая база, карта кода, первичные источники и границы выводов.
5. **`AGENT_PROMPT.txt`** — готовое сообщение агенту. Можно приложить весь ZIP и отправить этот текст.
6. **`fixtures/magnet-example.json`** и **`fixtures/verify-magnet.mjs`** — маленький воспроизводимый пример новой механики на настоящих правилах Seeds.

## Что делать первым

**A: текущая монетизация → B1: Магнит → B2: стратегический план.**

Сначала завершить корректный путь «нажал подсказку → посмотрел видео → получил подсказку» и измерение. Затем сделать отдельный кандидат Магнита в Classic. Стратегический план разрабатывать следующей изолированной итерацией. Изменение рекламного перехода после результата — отдельный эксперимент A4. Испытания и перестановка остатка — специфицированные лабораторные прототипы B3/B4, выключенные для аудитории.

**Не включать всё одновременно:** разные блоки имеют независимые флаги и собственные результаты проверки. Работа не требует нового магазина, общей валюты, backend или переделки всей архитектуры.

## Границы поручения

Реализовать, проверить и подготовить ревьюируемый результат в репозитории Seeds. ТЗ не поручает публикацию в RuStore, включение живого рекламного эксперимента, изменение других игр или перенос игровых материалов в `mini-games-kit`. Рутинные технические решения и исправление обнаруженных дефектов внутри согласованного объёма агент принимает самостоятельно.

В итоговом отчёте раздельно указать: **реализовано → проверено в тестовой сборке → доступно аудитории → коммерчески подтверждено**. Нельзя перескакивать между этими статусами по результатам CI или синтетических полей.

## Как проверить пример Магнита

Нужен Node 24+ и checkout Seeds с правилами из указанной базы:

```sh
node --experimental-strip-types fixtures/verify-magnet.mjs /absolute/path/to/seeds-bits
```

Скрипт только читает настоящий `src/core.ts` и JSON из пакета. Он проверяет исходную последовательность обычных ходов, отсутствие обычной пары до Магнита, недопустимость магнитной пары по обычным правилам и допустимость двух завершающих ходов. Сам магнитный переход в скрипте — иллюстрация предлагаемого правила, а не готовая production-реализация.
