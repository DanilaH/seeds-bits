## Контракт

RecordCompletion/collectPair, экономика, wire, история, ревизии раскладок, Core Feel поля, рекламные gates и шесть paused flags не менялись. Последний Classic pair переносит свои прежние+2 в result presentation после commit; дополнительного начисления нет. Анимация/таймер/звук не подтверждают запись и не блокируют управление. При навигации/фоне/resize/reduced motion отображается точный durable итог, устаревшая последовательность не возобновляется. Коллекция при открытии даёт только settle, не «заработано».

Применены UI Motion Recipes, Owned DOM Motion, Stable Progress UI и Tier Progress из kit; установленный owned-dom-motion/value-transfer pin неизменён. Повторно применяются существующие API, не новый общий runtime. KIT IMPACT — REUSE. Общий kit не менялся.

## Приёмка и медиа

`e2e/menu-reward-feel.spec.ts` проверяет реальные компоненты и кадры, включая сохранение под настоящим Web Lock и ошибку записи; `tests/result-presentation.test.ts` — новизну milestones. Исходный11-сценарный `scripts/independent-menu-feel.mjs` сохраняется отдельно и запускается на12106 и новом runtime. Его таймеры — выборка движения, не save barrier.

`record-menu-reward.mjs` повторяет рецепт Core Feel recorder: реальные CDP frames с timestamp и живой application WebAudio mix через MediaStreamDestination; звук не подменяется дорожкой. Четыре сцены: jar/task, новый том, новая медаль+банка, навигация. Для каждого before/after записываются MP4, actual tap times/audio offset и source. Это desktop Chromium с синтетическими сохранениями, не Android audio capture и не физический телефон. Контейнер60fps не является доказательством60fps рендера; фактическое число кадров сохранено в recording.json.

Прежние проверки количества частиц и траекторий обновлены на новый точный контракт12 и локальный радиус54px; однократность, persistence, opt-out, отмена и отсутствие эффекта до commit сохраняются. Полный landscape сохраняет прежние3 колонки; адаптивность колонок применяется только к portrait.

Локально TypeScript/web build и177 unit PASS. Перед выдачей требуются полный project CI, новый focused gate, исходный динамический аудит before/after, звуковые записи, native demo/offline на точном итоговом SHA и подписанный preview12107. Точные final runs, source и APK SHA закрепляются в PR40/выдаваемом протоколе. Физический телефон, оценка ощущений/вибрации в руках, TalkBack и аудитория UNKNOWN.

## Дополнительная проверка native baseline

На31a8882 demo остановился до первой проверенной навигации: [сохранённый FAIL/artifact15153680354](https://github.com/DanilaH/seeds-bits/actions/runs/45894307086/artifacts/15153680354). `initial` относился к draw54925/revision5/screenTop1124; за92ms insets завершили перестройку, revision6/7 уже1076. Переход произошёл при expected=false. Сохранённый PNG старта и PNG отказа оба содержат рекламу на1076; статическая область(140,1076)–(608,1176),46800 RGB-пикселей, полностью совпала. Отличается анимированный левый значок креатива. Это не доказательство смещения рекламы на переходе «поле→результат».

Причина отказа — смешение старой геометрии и более позднего снимка в QA `paint(initial)`. Приёмка теперь связывает draw→PNG→draw на одной ревизии, с готовой портретной native рамкой и полной рекламой внутри WebView. Сохраняются оба draw и причины отклонённых начальных проб. Контрольный PNG берётся из той же пробы. После включения expectation дополнительно проверяется исходная точка до первого ввода; strict равенство координат/view/request, per-draw0 moved/hidden и все fullscreen/modal проверки прежние. Позиционирование, insets policy и SDK не менялись. Четыре unit-регрессии используют фактические координаты отказа; задержки для обхода инварианта не добавлялись.

Полный регресс также выявил коллизию диагностического `data-index` банки с селекторами клеток после результата: используется отдельный `data-jar-index`. Маршрутные эффекты перемещаются по вертикали, а раскрытие страницы идёт от левого корешка внутрь; это сохраняет scrollWidth на промежуточных кадрах, включая широкие экраны. Локальные страницы плавно проявляются без transform: масштабирование всей сетки кратковременно уменьшало календарные hit targets ниже44px (591/592 в CI4bc3161). Инвариант44px оставлен строгим; focused сценарий теперь дополнительно проверяет каждый кадр смены месяца на320px.
