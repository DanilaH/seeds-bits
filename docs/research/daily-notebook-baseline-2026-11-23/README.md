**Наша игра «Семечки», рабочая ветка PR №9. Срез:** `df9ff5c3df8b017803e2ff924c2812a5efc530ac`, runtime исправлений Классики `eae2bcbeaaa1a5c76872dddc7a7f79844988b60e`. **Предыдущая приёмка:** `7f8ac0e05a338d4101d10f680720343b6881ba9a`.

## Главное

**Исправления Классики не изменили тетради и ежедневные задачи.** [Сравнение 7f8→df9](https://github.com/DanilaH/seeds-bits/compare/7f8ac0e05a338d4101d10f680720343b6881ba9a...df9ff5c3df8b017803e2ff924c2812a5efc530ac) меняет генератор/измеритель Классики, тесты и сопровождающие материалы. `puzzles.ts`, оба notebook JSON, `notebooks.ts`, `daily-run.ts`, `jars.ts`, `progress.ts`, `main.ts`, core и codec истории не менялись. Поэтому четыре сложности Классики не создают четыре сложности в этих режимах.

Два подтверждённых основания следующей работы: **поздние тетради требуют значительно больше действий при той же верхней награде**, а **ежедневные задачи не имеют заданного недельного ритма**. Это основания для проверки темпа/ощущения, не доказательство скуки или оттока. Буквальных дублей в текущих 2400 задачах и 365 днях 2026 не обнаружено.

## 1. Тетради: устройство и подтверждённый рост

Тетрадь — **фиксированный каталог**, а не runtime-выдача по выбранной классической сложности. Первые 24 поля и пути хранятся в `notebook.json`, следующие 2376 — в `notebook-extra.json`. Номера `book-v1-25`…`book-v1-2400` выводятся из положения в extra; перестановка строк extra меняет содержимое уже существующих ID. Загрузка extra лениво выполняется при входе в том>1, но загружается сразу весь extra, не одна выбранная тетрадь. Границы: [puzzles.ts:1–7,99–123](https://github.com/DanilaH/seeds-bits/blob/df9ff5c3df8b017803e2ff924c2812a5efc530ac/src/puzzles.ts#L99-L123), [main.ts:3511–3545](https://github.com/DanilaH/seeds-bits/blob/df9ff5c3df8b017803e2ff924c2812a5efc530ac/src/main.ts#L3511-L3545).

Всего **100 томов по 24**, в томе четыре страницы по 6. Есть 10 названий разделов, свободный выбор тома/задачи и фильтры «все / новые / в процессе / завершённые». Жёсткой блокировки следующего тома до завершения предыдущего в этом UI нет. Рекомендованное продолжение выбирает текущую незавершённую, начатую либо первую нерешённую задачу; `nextTask()` идёт вперёд и затем обходит каталог с начала. [notebooks.ts:2–23](https://github.com/DanilaH/seeds-bits/blob/df9ff5c3df8b017803e2ff924c2812a5efc530ac/src/notebooks.ts#L2-L23), [main.ts:3663–3723](https://github.com/DanilaH/seeds-bits/blob/df9ff5c3df8b017803e2ff924c2812a5efc530ac/src/main.ts#L3663-L3723), [puzzles.ts:170–180](https://github.com/DanilaH/seeds-bits/blob/df9ff5c3df8b017803e2ff924c2812a5efc530ac/src/puzzles.ts#L170-L180).

## 2. Ежедневные: стабильное поле по дате, без недельной политики

`daily(day)` использует ID `daily-v1-YYYY-MM-DD`, seed `hash("seeds-daily-v1:" + day)`, запрашивает `8 + hash(day)%9` пар в `4 + hash(day)%2` рядах. Reverse construction записывает полный путь без Add. Недельного расписания, истории предыдущих дней, целевого профиля или уровня навыка здесь нет. [puzzles.ts:24–97,124–130](https://github.com/DanilaH/seeds-bits/blob/df9ff5c3df8b017803e2ff924c2812a5efc530ac/src/puzzles.ts#L124-L130).

| Срез 2026 | Фактический результат |
|---|---:|
|Даты / точные уникальные поля / replay сертификатов|365 /365 /365|
|Непустые цифры|16…32, медиана 24|
|Логическая длина|36 у 182 дней;45 у 183 дней|
|Медиана начальных допустимых пар|19|
|Полная очистка стратегией «первая пара, без Add»|273/365|
|Есть reading-ход в сертификате|336/365|
|Скачок количества цифр между соседними датами≥8|91/364 переходов|
|Тот же скачок≥12|59/364 переходов|
|Награды 4 /6 /8 семечек|38 /165 /162 дня|

Все ключевые числа issue №14 воспроизведены **исполнением исходного продукта**, а не прежним независимым портом. Формулировку «однообразные ежедневки» данные сами по себе не доказывают: поля уникальны, а ощущение однообразия не измерялось. Обнаружено отсутствие спроектированного ритма при едином способе построения.

Простой текущий пример:23…29 ноября дают 30,32,16,18,28,30,32 цифры. Падение 32→16 между 24 и 25 ноября следует из хеша, не из решения о дне отдыха. Это иллюстрация реализации, а не предложение изменить именно эти даты.

Архив начинается **01.01.2025**; будущие и некорректные календарные даты закрыты UI/проверкой `availableDay`. Прошлые дни доступны в любое время. После решения `nextTask()` сначала ищет следующую доступную нерешённую дату, потом предыдущие в архиве. [puzzles.ts:132–160,181–195](https://github.com/DanilaH/seeds-bits/blob/df9ff5c3df8b017803e2ff924c2812a5efc530ac/src/puzzles.ts#L146-L160), [main.ts:3511,3728–3751](https://github.com/DanilaH/seeds-bits/blob/df9ff5c3df8b017803e2ff924c2812a5efc530ac/src/main.ts#L3728-L3751).

## 3. Правила, помощь, награды и сохранения

**Терминология:** `meta.wallet` — общий запас дополнительных **подсказок**, отдельный от семечек в `jars`. `hintsLeft()` прибавляет к нему ещё не использованные из трёх бесплатных подсказок текущей попытки; `spendHint()` расходует общий запас после этих трёх. Поэтому сохранённый `wallet=7` не обязательно равен всему доступному остатку подсказок. Награда за дневную серию добавляет 1 или 3 именно в этот запас, а не семечки. Источник: [hint-budget.ts:15–26](https://github.com/DanilaH/seeds-bits/blob/df9ff5c3df8b017803e2ff924c2812a5efc530ac/src/hint-budget.ts#L15-L26), [daily-run.ts:47–55](https://github.com/DanilaH/seeds-bits/blob/df9ff5c3df8b017803e2ff924c2812a5efc530ac/src/daily-run.ts#L47-L55).

- **В обоих режимах Add запрещён**, кнопка скрыта. Доступны Undo/Hint; при отсутствии пар показывается restart. Поэтому бесперспективный ход здесь отличается от тупика Классики, где ещё можно добавлять. [main.ts:2086–2087,2135–2139,2579–2583](https://github.com/DanilaH/seeds-bits/blob/df9ff5c3df8b017803e2ff924c2812a5efc530ac/src/main.ts#L2571-L2584).
- Подсказка использует проверенный witness и ограниченный поиск. **Бюджет 2000 состояний при>100 оставшихся цифрах, иначе 50000; внешний таймаут 2500 ms.** UNKNOWN не объявляется доказанным тупиком. Может быть предложен возврат к проверенному прежнему состоянию. [advice-worker.ts:8–18](https://github.com/DanilaH/seeds-bits/blob/df9ff5c3df8b017803e2ff924c2812a5efc530ac/src/advice-worker.ts#L8-L18), [advice-client.ts:16–28](https://github.com/DanilaH/seeds-bits/blob/df9ff5c3df8b017803e2ff924c2812a5efc530ac/src/advice-client.ts#L16-L28), [main.ts:2668–2728](https://github.com/DanilaH/seeds-bits/blob/df9ff5c3df8b017803e2ff924c2812a5efc530ac/src/main.ts#L2668-L2728). Phone latency после отклонения от witness на поздней тетради не измерена.
- На book78 вновь проверены четыре исходных хода: `(7,16)` → `dead`, остальные три → найденное продолжение. Это законный, но невыигрышный выбор в режиме без Add, не доказательство неработающих нажатий. Уже имеется issue12; новый такой bug не создаётся.
- Семечки за задачу выдаются **один раз на ID**, при первой полной очистке: `min(24,max(4,ceil(pairCount/4)*2))`, где pairCount берётся из исходного снимка. Повторное прохождение увеличивает статистику попыток, но не повторяет уникальную награду. Том 100 не платит за каждую снятую пару, в отличие от Классики. [progress.ts:337–355](https://github.com/DanilaH/seeds-bits/blob/df9ff5c3df8b017803e2ff924c2812a5efc530ac/src/progress.ts#L337-L355), [jars.ts:113–115](https://github.com/DanilaH/seeds-bits/blob/df9ff5c3df8b017803e2ff924c2812a5efc530ac/src/jars.ts#L113-L115).
- Дневная серия учитывает только решение задачи **сегодняшнего дня сегодня**: 1 дополнительная подсказка на третий день, 3 — на каждом дне серии, кратном 7; повтор и откат даты не платят. Архив засчитывается в месячный трофей, а не в текущую серию. Бронза 7 различных дней, серебро 14, золото весь месяц; отдельной выплаты за сам трофей эти функции не добавляют. [daily-run.ts:9–10,39–55](https://github.com/DanilaH/seeds-bits/blob/df9ff5c3df8b017803e2ff924c2812a5efc530ac/src/daily-run.ts#L39-L55), [puzzles.ts:155–160](https://github.com/DanilaH/seeds-bits/blob/df9ff5c3df8b017803e2ff924c2812a5efc530ac/src/puzzles.ts#L155-L160).
- Сессии/Undo/scroll/hints хранятся по точному task ID. Переключение публикует новый режим после сохранения; законченная задача при повторном входе создаётся с тем же исходным полем. История завершённой задачи очищается при уходе из неё; история незавершённой сохраняется. [main.ts:3548–3608](https://github.com/DanilaH/seeds-bits/blob/df9ff5c3df8b017803e2ff924c2812a5efc530ac/src/main.ts#L3548-L3608). Wire6 и защита прав не изменились.

## 4. Что нельзя тихо менять

`progress.validId` принимает только classic, book-v1-1…2400 и daily-v1 с валидной датой от 2025-01; награды, done, hints, sessions, attempts, трофеи и activePuzzle используют эти идентификаторы. [progress.ts:29–35](https://github.com/DanilaH/seeds-bits/blob/df9ff5c3df8b017803e2ff924c2812a5efc530ac/src/progress.ts#L29-L35).

Следовательно, переупорядочивание notebook-extra или замена hash/reverse construction дневной задачи задним числом затронет перезапуск, подсказку и идентичность уже сохранённой задачи. Новая версия/каталог требует отдельной политики ID и даты вступления в силу; простого переименования префикса недостаточно из-за валидаторов, календаря и наград. Существующие поля, сертификаты, незавершённые сессии, Undo и уникальность награды нужно закрепить fixtures. Недельный ритм и новые серии не означают разрешение менять экономику.

## 5. Новая optional metadata Классики: регресс не обнаружен

Повреждённые optional scenarios фильтруются отдельно. [classic-generator.ts:26–94,299–314](https://github.com/DanilaH/seeds-bits/blob/df9ff5c3df8b017803e2ff924c2812a5efc530ac/src/classic-generator.ts#L26-L94).

После хода/сохранения новый код прочитал их с **0 recovery**, сохранил поле, Undo, current, seed, recent, notebook/daily, общий запас 7 дополнительных подсказок (`meta.wallet`), 74 семечка в jars и запасы Magnet3/Plan2. Единственное ожидаемое удаление — старая rotation. Следующая High45 записывает новый scenario. На 8 новых High-партиях roundtrip сохраняет именно фактически выбранные recipe/motif и ограничение 4; испорченные optional записи не удаляют current/recent/seed.

Это **ACTUAL SOURCE NODE**. Проверки установки 12082, WebView и физического телефона оцениваются отдельным аудитом; сюда не приписываются.

## Воспроизведение и содержимое пакета

Это упаковка уже выполненного аудита для docs PR; новых продуктовых изменений или расширения тестовой выборки при упаковке нет. Нужен Node 24 и checkout `DanilaH/seeds-bits`, содержащий три закреплённых commit: текущий `df9ff5c3df8b017803e2ff924c2812a5efc530ac`, предыдущий `7f8ac0e05a338d4101d10f680720343b6881ba9a` и legacy `0c8fbba9c8864f39a398c5a6517b7b493ae3b1fc`.

Из корня checkout:

```bash
node docs/research/daily-notebook-baseline-2026-11-23/content-audit.mjs
```

По умолчанию новый запуск пишет `results.json` и `rows.json.gz` в `test-results/daily-notebook-baseline/`, сохраняя приложенные результаты. Если checkout расположен отдельно, задать `SEEDS_AUDIT_REPO=/absolute/path/to/seeds-bits`; каталог новых результатов можно задать через `SEEDS_AUDIT_OUTPUT`.

Загрузчик читает только `git show <pinned-SHA>:<path>`, сверяет Git blob и SHA256 каждого исполняемого TS/JSON и прекращает работу при несовпадении. Он не зависит от scratch snapshot, текущих незакоммиченных файлов, npm, браузера или APK. Временные скомпилированные модули удаляются при завершении процесса; меняются только TypeScript/import resolution и необходимый Node JSON import attribute.

В пакете: README с выводами; `results.json` со сводкой и границами метода; компактный `rows.json.gz` со всеми исходными строками измерений; `manifest.json` с точными версиями/хешами и ссылками на ранее прочитанные материалы; `source.mjs` и `content-audit.mjs` для повторения. Хеши файлов опубликованных данных указаны в manifest.
