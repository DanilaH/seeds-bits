## A. Вход без межстраничной рекламы

Решение владельца заменяет соответствующие маршруты из №27/31. Речь об interstitial; этот пункт не меняет постоянный баннер и добровольную rewarded-подсказку.

- Холодный запуск, первый старт на чистом профиле, восстановление сохранённой игры, Resume из первого меню после запуска и возврат из настоящего фона не вызывают показ interstitial. Первый переход из стартового меню к полю тоже защищён, если игрок выбрал новую партию вместо Resume.
- Вход на поле и последующий переход между партиями — разные действия. `Дальше` после завершённой Классики остаётся рекламной точкой через существующий общий gate. Открытие выбора сложности и его отмена рекламных запросов не создают.
- Сохранить общий cooldown, suppression после внешних экранов и rewarded, сериализацию запросов, offline/no-fill. Не создавать таймер, который через несколько секунд всё-таки выдаёт отложенную рекламу за вход.
- Защита входа заканчивается после фактического первого открытия игровой доски. Возврат из собственного рекламного fullscreen не должен ошибочно считаться новой пользовательской сессией или сбрасывать cooldown. Настройки/диалог тоже не создают новый app entry.

**Приёмка:** чистая установка; update с незавершённой Классикой/тетрадью/днём; закрытие процесса → Resume; Home телефона → возврат; первая новая Классика с выбором сложности; собственный rewarded fullscreen → возврат → следующий разрешённый переход. Для входов `show(interstitial)` не вызывается вообще; для следующей партии решение принимает существующий gate. Нужны trace маршрута/причины и запись native SDK test ads. Отклонённый показ не съедает продолжение и не теряет сохранение.

## D. Тупик и неудачная подсказка

Один спокойный бумажный акцент рядом с полем вместо конкурирующих статусов и нескольких мелких ссылок. Он появляется в видимой области без прокрутки и остаётся, пока состояние актуально. Поле можно просмотреть, Undo остаётся доступна. Для срочного сообщения сохранения эта карточка уступает место.

| Факт игрового состояния | Текст и действие |
| --- | --- |
| Классика: пар нет, Add помещается | «Пар больше нет» + «Добавьте оставшиеся цифры»; основное действие «Добавить N», вторичное «Отмена», если есть история. Это продолжение партии, не поражение |
| После Add снова нет пар | «Добавлено N цифр. Пар пока нет» + следующее реальное Add; не показывать идентичный необъяснённый статус |
| Классика: технический предел поля | «Поле заполнено» + доступная отмена/новая партия; Add не обещать |
| Тетрадь/день: ноль легальных пар | «Пар больше нет» + понятный выбор отмены или «Начать заново». Рестарт сохраняет назначенную задачу/дату |
| Подсказка доказала dead, есть recovery | «Из этого положения решение не получается» + «Вернуться на N ходов»; «Начать заново» — вторичное действие |
| Подсказка доказала dead без recovery | Явное объяснение + заметная «Начать заново», даже если ещё существуют легальные пары |
| Solver вернул UNKNOWN | «Не удалось проверить продолжение»; проверенный откат можно предложить, но нельзя объявлять поражение или отсутствие решения |

№6 не сводится к №7: есть dead с оставшимися легальными парами. Проверять обе ветки `hint()`. Не списывать подсказку за отсутствие показываемого хода. Не возвращать Магнит/План и остальные приостановленные продукты.

**Исходные сценарии:** `docs/porting/2026-11-20/double-add.json` (двойной Add); `book-v1-78` из e2e/notebook-78-phone-report.spec.ts (тупиковый выбор); existing `task-rollback` и `hint-repair` fixtures. При необходимости закрепить найденный dead-with-legal-moves и UNKNOWN fixture. Это тестовые состояния, не изменение выдачи.

**Приёмка:** получить каждое состояние действием игрока; карточка читаема и нажимается с начальной позиции на 320×568 с баннером. Undo/restart меняют фактическую доску, устаревшая карточка исчезает. Смена режима во время solver не показывает старый результат. Рестарт проходит существующее подтверждение и не меняет награды/пины контента.

## E. Классика: «Дальше» и «В меню»

Основная широкая CTA **«Дальше»** по центру → существующий выбор четырёх сложностей. Подтверждённый выбор → ровно один `beginClassic("next", level)` → сохранение → существующий общий рекламный gate → новое поле. Отмена выбора возвращает тот же финал; показов и генераций нет. Быстрый двойной tap не создаёт второй запрос/доску.

**«В меню»** — самостоятельное вторичное действие под CTA, визуально по центру. Верхняя кнопка меню может сохраниться, но не заменяет явного действия финала. Удалить наследование трёх колонок старых easier/again/harder. На «Дальше» не проводить промежуточный маршрут через Home и второй рекламный запрос. Остальные разрешённые рекламные переходы подчиняются прежнему общему gate.

**Приёмка:** каждая сложность; отмена/Back; no-fill/offline/error; cooldown/rewarded suppression; повторный tap; save failure; релонч. Выбранная сложность/seed/сохранение согласованы с новым полем, прошлое завершение и семечки не начисляются заново. Старые решения №31/PROJECT_DECISIONS про единственную «В меню» этим требованием явно заменены.

## G. Непосещённый дейлик и зелёный фон

В `calm-screens.css` `today-calendar-glow` бесконечно меняет **background-color** календаря. Новый `quiet-table.css` задаёт SVG через background, но анимация продолжает рисовать цвет под прозрачными участками картинки. Это проверенный конфликт CSS; телефонная воспроизводимость именно жалобы отдельно открыта.

Убрать изменение фона и старую анимацию этого слоя. Акцент дать движением самой маленькой иллюстрации либо отдельным мягким световым ореолом: например, одно покачивание ±1–1.5° за 400–600ms, затем пауза 6–9s. Не анимировать геометрию соседних кнопок. Период и амплитуда — предлагаемая настройка, не референсный факт.

Акцент действует только `!doneToday && !openedToday`. Вход на поле сегодняшней задачи прекращает его, даже если ни одной пары ещё не снято. Признак фактического открытия хранить по локальной дате; `sessions[id]` или назначение контента не всегда доказывают вход. Предпочесть имеющийся достоверный признак, иначе добавить совместимую метку без переписывания progress. После полуночи отметить новый день, не предыдущий; смена даты во время паузы также учитывается.

**Приёмка:** не открывал → открыл без хода → вернулся → перезапустил приложение → решил → наступил следующий день; обе темы, reduced motion, offline. После открытия акцент не возвращается в этот день. Календарь сохраняет бумажный вид; зелёной прямоугольной подложки нет на всех фазах анимации. Reduced motion оставляет неброскую статическую отметку доступности.

## H. Тетрадка меню: пустое состояние, касание, левитация

Тетрадка всегда занимает своё место. Текущее продолжение показывает честный режим/прогресс/реальный фрагмент поля. Без партии для продолжения показать готовую стартовую тетрадку с заголовком **«Новая игра»** и CTA **«Начать»**. Нажатие ведёт к существующему выбору сложности Классики; сама тетрадка действует точно как кнопка под ней. До подтверждения не создавать «сохранённую партию» и не выдавать случайный mock field за текущую доску. Для чистого FTUE сохранить настоящий маршрут первой учебной задачи.

Сделать иллюстрацию отдельной доступной кнопкой; не вкладывать button в button. Общий обработчик действия для тетрадки и CTA, один доступный label. Fixed hit target, движение только внутренней графики. Enter/Space, pointer cancel, тап у края и быстрый двойной тап работают предсказуемо.

Начальная анимационная настройка: вертикальное движение 3–4px за цикл 4–6s, без постоянной тряски. Чем выше тетрадка, тем мягче/шире и менее плотная тень; при снижении тень плотнее/уже. Тень остаётся отдельным слоем на столе. Тап даёт короткую посадку/press; не бороться несколькими transform-анимациями на одном узле. На скрытом Home/в фоне эффекты остановлены; reduced motion — статическая тетрадка.

**Приёмка:** чистый профиль, завершённая Классика, все доступные задачи тома решены, доступное продолжение каждого режима; обе темы, маленький экран. Объект не исчезает, меню не превращается в пустое место. Тап по рисунку/CTA ведёт одинаково, не открывает две партии; при отмене выбора прогресс/сейв прежний.

## I. Дейлик: медаль на итоговой тетрадке и «В меню»

Сцена: дата и «Задача дня решена» → крупная текущая медаль с месяцем и числовым прогрессом **прямо на тетрадке** → одна компактная строка заработанного → широкая **«В меню»** над баннером. Календарь можно оставить вторичным действием, если он помещается; он не заменяет Home. Не дублировать медаль в длинном award ниже тетради.

Использовать действующие `trophy()`/`trophyMark()`: бронза — **7** решённых дат месяца, серебро — **14**, золото — **все даты месяца**. Это не длина текущего streak. Дейлик из архива продвигает свой месяц; повторное решение одной даты не добавляет единицу. Пример до первого порога: «Бронза · 4 из 7» / «Ещё 3 дня». На 7-й/14-й/последней дате месяца показать полученную медаль как главный итог, затем короткую следующую цель. Не заменять факт получения сразу незаполненной следующей медалью.

Обычное завершение двигает заполнение **с прежнего подтверждённого количества к новому** и даёт короткий блик/акцент тетрадки. Новая медаль — усиленный праздник из C. Pending save не показывает «получена», save failure оставляет понятный retry. Повторное открытие показывает конечную статическую медаль без нового прироста или салюта. Прогресс остаётся виден при выключенных эффектах.

**Приёмка:** месячный count 0→1, 6→7, 7→8, 13→14, 14→15, total−1→total; месяцы по 28/29/30/31 дню; архив другого месяца; replay уже решённой даты; save failure/retry; mute/reduced motion; app background. Все состояния без прокрутки на матрице B. Кнопка «В меню» открывает Home с уже обновлённым прогрессом, не запускает другую задачу.
