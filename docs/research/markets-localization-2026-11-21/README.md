# «Семечки» · площадки, языки и аналитика запуска

ТЗ для разработчика «Семечек» · 21 ноября 2026. Рабочая база — [PR № 9][pr9], проверенная [ревизия 145a5124][base], preview 1.1.2 (12066). Цель — видеть источник первого запуска каждого измеряемого размещения и дать игроку пройти весь путь от первого хода до возвращения в игру на выбранном языке.

## Что сдать и в каком порядке

| Пакет | Что сделать | Как владелец проверит результат |
| --- | --- | --- |
| A · Каналы | На Android перенести определение магазина из ветки NashStore. В вебе начать с Яндекс Игр. Для каждого следующего размещения использовать общий реестр. | В тестовом отчёте видны подтверждённый магазин, отдельно запуски файла с меткой канала, а в вебе — портал первого входа и сеть распространения. |
| B1 · Первая сборка | Добавить переключатель, вынести пользовательские строки и закончить русский, английский, испанский, турецкий и бразильский португальский. Начать одновременно с A. | Пять локалей работают офлайн в игре и собственных Android-уведомлениях. Сохранённая партия переживает смену языка. |
| B2 · Расширение до десяти | Сразу готовить французский, немецкий, итальянский, вьетнамский и индонезийский. Использовать те же ключи. Выпуск B1 возможен отдельно. | Каждая из пяти дополнительных локалей проходит ту же приёмку. Готовое покрытие международного выпуска — десять языков. |
| C · Аналитика | Согласовать имена событий и параметры в начале A/B1. Подключить разрешённых получателей и построить отчёты. | Владелец может выбрать период и канал, увидеть установку или первый веб-вход, запрошенный и показанный язык, переключения, первый самостоятельный ход и возврат D1. |

После проверки пакета продолжать следующий. Если конкретный магазин ещё не дал доступ к кабинету, записать, какая проверка ждёт доступа, и продолжить независимо доступные каналы и переводы.

## Реестр площадок

В реестре 41 площадка портфеля. Для каждой указан постоянный ID и плановый приоритет. Для «Семечек» фактические размещения добавляются по мере публикации. [Реестр идентификаторов](./channels.json) · [Обоснование языков и сведения об аудиториях](./AUDIENCE.md)

| Формат | Основные | Потенциальные |
| --- | --- | --- |
| Веб, 25 | Яндекс Игры, GamePush, Пикабу Игры, VK Игры, Одноклассники, CrazyGames, Y8, GameDistribution, GamePix, GameMonetize, Kongregate, Coolmath Games, PlayDeck, WG Playground, VK Play, билайн, Фотострана | Playgama, Poki, Telegram Mini Apps, MAX Mini Apps, YouTube Playables, itch.io, Newgrounds, Game Jolt |
| Android / APK, 16 | RuStore, NashStore, Uptodown, RuMarket, Huawei AppGallery, Xiaomi GetApps, TapTap, ONE Store | Google Play, Samsung Galaxy Store, OPPO App Market, HONOR App Market, Aptoide, Amazon Appstore, APKPure, Softonic |

В отчёте о подключении вести по одной строке на игру, канал и вариант размещения. Указать доступ к публикации, сборку, доступные метрики, способ атрибуции, дату контрольного запуска, ссылку на строку отчёта и статус проверки. Для агрегатора указывать также конечный портал, если он известен. Статус «планируется», отсутствие доступа и нулевое число запусков должны различаться.

## A. Надёжно определить площадку

### Android

1. Перенести из ветки NashStore `SeedsInstallStore`, его регистрацию в генераторе Android-проекта и существующую передачу `install_store` в свойства профиля AppMetrica и в события. В release уже сохраняется первый результат в `seeds-monetization`, обрабатываются API 30+ и старый API. В коде известны `ru.vk.store → rustore`, `com.nashstore → nashstore`. В preview 12066 класс отсутствует, а `build_channel` означает лишь `release/preview`. При переносе сохранить ранее записанные значения и смысл публичного поля. [Детектор релизной ветки][detector] · [Профиль и события релизной ветки][oldreport] · [Текущий отправитель][report] · [Генератор][build].
2. На первом пользовательском запуске фиксировать `install_store` из известного пакета установщика, `store_evidence` (чем подтверждено), `artifact_channel` (куда выпущен этот файл) и `acquisition_state` (`fresh`, `legacy`, `undetermined`). Фиксация однократная, устойчива к повторам и смене магазина обновления. Использовать уже захваченное значение NashStore/RuStore. Если известна лишь прежняя запись, источник доказательства обозначить `legacy_record`. Обновление прежней версии без записи — `legacy/unknown`. При неясной миграции — `undetermined`; обе группы исключить из числа новых. Старые данные о канале не восстанавливать догадкой. [Android InstallSourceInfo][android].
3. Для новой установки на API 30+ сначала проверить инициатора, затем установленный системой пакет-установщик по реестру. До API 30 использовать совместимый путь релизной ветки. Отсутствие данных, установка из файла или неизвестный посредник дают `unknown`. Если два **известных разных** магазина названы одновременно, оставить `unknown/conflict` для разбора. Не отправлять сырые имена произвольных пакетов. Для нового магазина добавить соответствие только после реальной установки через его клиент или документированной контрольной проверки. Текущий генератор выставляет android:allowBackup="false". При обновлении и переносе данных проверить, что маркер атрибуции не переезжает на другой экземпляр установки. [Android API][android] · [Резервное копирование Android][backup].
4. Для каталогов со скачиванием APK через браузер ОС часто видит общий установщик. На таких каналах использовать отдельную метку артефакта, заданную при выпуске, если нужна разбивка: например, `artifact_channel=uptodown`, `install_store=unknown`, `store_evidence=unavailable`. В отчёте это **«первый запуск файла, подготовленного для Uptodown»**. Пересланный APK сохраняет ту же метку. Один общий файл, скачанный из двух таких каталогов, задним числом разделить нельзя. Оставить существующие package ID, подпись и путь обновления. Проверенная рекламная ссылка и AppMetrica tracker — отдельные поля рекламной атрибуции.
5. Новые значения магазинов брать из [channels.json](./channels.json). Группы `primary/candidate` относятся к плану владельца. Для каждого фактического выпуска приложить строку «канал, package ID, версия, SHA256 файла, метка сборки, клиент/установщик, способ проверки, дата». Amazon из прежнего списка применим только к совместимым устройствам Fire. [Статус Amazon Android][amazon].

### Веб / HTML5

1. Первый канал — **Яндекс Игры**. В настройках сборки для этой площадки задать `portal_id=yandex_games`, считать успешную инициализацию SDK отдельным подтверждением. Для CrazyGames, VK, OK и следующих порталов использовать тот же адаптер. Возвращать `portal_id` (где играли), `distributor_id` (через кого доставили), `portal_evidence` и возможности приёмника событий. Пример: открытие игры в ОК через GamePush даёт `ok_games / gamepush`; засчитывается один запуск. Если у многопортальной сборки известна только сеть — `unknown / gamepush`. Для самостоятельного хоста — `direct_web` только при известном собственном домене. На чужом хосте копия не должна стать подтверждённым порталом по одной метке файла.
2. Для признака портала предпочитать официальный контекст SDK, согласованный с размещением. Затем — однозначный размещённый вариант с проверяемым origin из списка канала; различать это доказательство и ответ SDK. Голый query-параметр, UTM, общий CDN, подставленный или пустой referrer не доказывают площадку. Расхождение пометить `conflict`. Не обращаться к произвольному родителю iframe. [Платформенный слой игры][platform] · [Публикация через GamePush][gp] · [GameDistribution][gd].
3. Для Яндекс Игр подключить счётчик по инструкции площадки, создать JS-цели под имена событий и проверить параметры вызова `reachGoal` в тестовом отчёте. Сейчас обычный `track()` идёт через native bridge, на обычном вебе этого приёмника нет. Развязать отправку аналитики и наличие рекламы; вызовы GameplayAPI сохранить для жизненного цикла игры. Для остальных порталов на подключении заполнить способ получения отчёта: свои разрешённые события, только агрегаты портала либо «телеметрия недоступна». Например, Poki по умолчанию ограничивает внешние запросы. При запрете внешней отправки или недоступном разрешении использовать доступные агрегаты; собственные переключения языка в таком срезе пометить «нет данных». [Текущий track][track] · [Яндекс Метрика для игр][ym] · [Правила Poki][poki-policy].
4. `web_first_play` — первый успешный вход в интерактивное поле для локального профиля данного портала. `portal_id` — часть ключа, включая общий домен сети; по возможности учитывать штатное разрешённое хранилище портала. Две вкладки, reload и возврат из фона не создают второй первый вход. При недоступном долговременном хранилище считать только веб-сессии, отметить `storage_scope=session_only`. Известное сохранение прежней версии пометить `legacy`. Очистка браузера может дать новый профиль; уникального человека между браузерами, порталами и Android не обещаем.

## B. Локализация и выбор языка

| Сборка | Коды и подписи в настройках |
| --- | --- |
| B1 | `ru` Русский · `en` English · `es` Español · `tr` Türkçe · `pt-BR` Português (Brasil) |
| B2, дополнительно | `fr` Français · `de` Deutsch · `it` Italiano · `vi` Tiếng Việt · `id` Bahasa Indonesia |

Для конкретного выпуска в Южной Корее, Тайване или материковом Китае отдельно поднять приоритет соответственно `ko`, `zh-Hant` или `zh-Hans`. Решение привязано к выбранной витрине и согласованию размещения. Японский, хинди, тайский, филиппинский и арабский остались в исследовательской очереди. [Основания по рынкам](./AUDIENCE.md)

[Пакет переводов](./launch-copy.json) содержит 118 обычных ключей и два с формами множественного числа на всех десяти языках. Здесь короткие и подробные команды обучения, объяснения ошибок пары, тетради, задача дня, нативные напоминания и тексты витрины. Для существующих текстов указан файл, для новых — пометка `new:`. Это исходный материал для интеграции. Полный список строк строится по фактическому коду и экранам. Использовать параметр `selector`, правило множественного числа текущей локали и ветку `other` для остальных категорий.

**Интерфейс.** Первая видимая строка настроек — значок глобуса, локализованная подпись `language.label` (на русском «Язык»), справа текущее значение. Нажатие открывает системный список или доступную панель с одиночным выбором: локализованный пункт «Автоматически», затем самоназвания названия доступных языков из таблицы B1/B2. Напротив активного значения галочка. Для длинного списка включить прокрутку самой панели. Текущий пункт доступен сразу при открытии, кнопка закрытия остаётся доступной. Для автоматики в строке настроек показывать фактический язык, например «Автоматически · Русский». В компактном меню паузы оставить доступный с первого уровня переход к языку через глобус, если настройки на текущем экране иначе нельзя найти без знания языка. Модальное окно при первом запуске не требуется. Флажки исключить: одно и то же название языка должно быть узнаваемо жителям разных стран. [Рекомендации W3C по самоназваниям][w3c].

**Как выбирать.** Когда есть явный выбор поддерживаемого языка, применить его. В «Автоматически» взять язык портала, далее список предпочтений Android/браузера, затем английский. На Яндекс Играх прочитать `ysdk.environment.i18n.lang` при запуске, до первого поля; на CrazyGames следовать локали его SDK и предписанному запасному EN. Портальная политика при недоступном языке имеет приоритет над общим списком устройства. Для Android учитывать системную настройку языка приложения, если она уже доступна пользователю; при интеграции с ней исключить расхождение системной настройки, WebView и нативных уведомлений. Нормализовать BCP 47: `en-GB→en`, `ru-KZ→ru`, `es-MX→es`, `es-ES→es`, `tr-TR→tr`, `pt-BR→pt-BR`. Если единственный доступный португальский перевод бразильский, `pt` и `pt-PT` также получают `pt-BR`; отдельно сохранить запрошенный вариант. В B2 нормализовать `fr-CA→fr`, `de-AT→de`, `it-IT→it`, `vi-VN→vi`, `id-ID→id`. На Яндекс Играх при неподдерживаемой локали SDK `be`, `kk`, `uk` или `uz` применять резервный RU, для остальных — EN согласно [таблице Яндекса][yfallback]. В аналитике отмечать причину резерва. Для китайского явно различать Hans и Hant. Если SDK поздно ответил или сеть пропала, дать играть на выбранном языке, без внезапной перерисовки посреди хода. [Яндекс SDK][ysdk] · [CrazyGames][cg] · [Android per-app languages][locales].

**Сохранение.** Ввести настройку `language_mode=auto|manual` и значение выбора; отсутствие старого ключа означает `auto`. Хранить отдельно от партии, обновить список разрешённых полей при чтении и слиянии настроек, включая веб-вкладки. При выборе сразу обновить интерфейс, доступные названия, `document.documentElement.lang`, в существующей панели переместить отметку и оставить фокус. Закрытие списка без выбора ничего не записывает. Переход EN → Auto при системном EN всё равно меняет режим. Смена языка посреди задачи сохраняет поле, выделение, ход, подсказку, дату, прокрутку и историю Undo. Изменение языка или региона не меняет игровую дату и ключ ежедневной задачи. [Сохранение настроек][platform] · [Даты и первые команды][first].

**Что переводить.** Вынести видимые строки в комплектные каталоги языков текущего пакета B1 или B2 с общими ключами, параметрами и множественными формами. Охватить меню и настройки, оба обучения, первую тетрадь, ошибки пары, подсказки и стрелки, сложность, действия, тупик и откат, победы, коллекции и трофеи, календарь, периоды и серии, согласия/отказы и состояния видеоподсказок, отсутствие сети, сохранение и восстановление, aria-label, заголовок документа, собственные системные уведомления Android и их канал. Указать поддерживаемые языки в активных витринах, подготовить согласованное бренд-название либо названия на поддерживаемых языках, краткое и полное описание и надписи на скриншотах для каждой публикуемой локали. Системные окна платформы тестировать отдельно. Стабильные ID задач, счетчиков, событий и покупок остаются техническими ключами. Отключённые эксперименты проходят только инвентаризацию общих ключей. [Первые команды][first] · [Причина хода][hint] · [Поле, настройки и результаты][main] · [Уведомление Android][reminder].

| Контрольная строка | RU | EN, стартовая редакция |
| --- | --- | --- |
| Переход после классики | Открыть тетрадь | Open puzzle book |
| Заголовок поля | Тетрадь 1 · задача 3 | Puzzle book 1 · Puzzle 3 |
| Цель обучения | Найдите одинаковые цифры или две, которые в сумме дают 10. | Match equal numbers or two numbers that add up to 10. |

Использовать правила множественного числа и форматирование дат выбранной локали. Дата архивной задачи берётся из ID открытой задачи. Поставлять переводы и необходимые шрифты в составе соответствующей сборки. В CI сверять наборы ключей и параметров. Ошибка перевода видна в QA; в сборке игрока аварийный резерв для строки — английский. Перед объявлением языка в витрине устранить найденные пропуски на всех доступных игроку экранах. Переводы в пакете прошли структурную проверку. Редакторская проверка и проверка понимания новичками относятся к приёмке сборки.

## C. Что отправлять и что считать

Контрольные строки: Android из RuStore — `surface=android, install_store=rustore, store_evidence=installer_package, artifact_channel=rustore`; тот же файл передали напрямую — `install_store=unknown, store_evidence=unavailable, artifact_channel=rustore`; веб в ОК через GamePush — `surface=web, portal_id=ok_games, distributor_id=gamepush`. Метка первого артефакта в когорте неизменна, даже если текущая версия получена другим каналом.

Для всех измеряемых новых событий передавать версию контракта, `surface`, фактический канал и основание определения, `build_channel`, `distribution_variant` при известной региональной витрине, `ui_language`, `language_mode`, `locale_source=manual|portal|device|fallback` и QA-признак. В исходном контексте сохранить нормализованный **запрошенный язык до перевода**, даже если сейчас он не поддерживается. Не записывать в `requested_locale` результат EN-fallback. Если сигнала нет — `unknown`. Когда ручной выбор меняет текущий язык, исходная когорта установки остаётся прежней. Из регионов передавать только нужные варианты из справочника; прочее сворачивать до языка или `other`. Без сырых URL, полного списка локалей и идентификаторов внешних аккаунтов. Для каждого устойчиво доставляемого события формировать `event_id` при записи в локальную очередь и повторно использовать тот же ID при отправке. Это позволяет убрать дубли при выгрузке. В отчёте Android использовать ID приложения из запроса выгрузки событий, если его нет в возвращаемых полях.

| Событие / показатель | Когда | Параметры и смысл |
| --- | --- | --- |

**Отчёт Android.** Зарегистрировать строковый профильный атрибут `install_store` в нужном приложении AppMetrica и проверить его на тестовой группе. Для воспроизводимой сводки выгрузить штатные установки и события, присоединить первый валидный контекст слева по `(application_id, installation_id)` внутри проекта. Дедуплицировать события по стабильному `event_id`, исключить QA, отдельно отразить `is_reinstallation`, `legacy`, `undetermined` и новые установки без контекста. Отсутствующий контекст не должен удалять установку из общего числа. Старым профилям и миграциям не приписывать источник последнего обновления. Иметь две подписанные колонки — подтверждённый магазин и файл с меткой канала. Подготовить владельцу сохранённый отчёт или воспроизводимую выгрузку с примером строки. [Профильные атрибуты][profile] · [Экспорт установок][installlogs] · [Экспорт событий][eventlogs].

**Отчёт веба и языков.** Рядом вывести отдельную таблицу «портал → новые профили с первым входом → самостоятельная пара → первая задача → D1». Воронку считать по уникальным профилям за одну и ту же когорту с одинаково доступными событиями. D1 — доля созревшей когорты с игровой активностью на следующий календарный день, с единой указанной зоной отчёта. Возврат засчитывается и при продолжении сохранённой партии. На границе дат учитывать первое игровое действие нового дня, даже если сессия началась накануне; повторные действия одного профиля за этот день дают один возврат. Отдельно вывести число открытий списка, уникальных открывших, смену режима/языка и матрицу «запрошенный → фактический». Не объединять в один показатель магазинное скачивание, Android Install, посетителя портала и новую веб-сессию. Для агрегатных платформ вывести их родную метрику и её определение; недоступные ячейки обозначить «н/д». Сравнивать конверсии до/после перевода внутри сопоставимых каналов.

Для языка считать долю открывших выбор среди активных профилей и долю изменивших настройку среди открывших за тот же период. Смену Auto ↔ ручной при том же языке показать отдельно от смены языка текста. Для списка следующих переводов считать первичный запрос неподдерживаемого языка по новым профилям и фактически открытым каналам. Сохранять крупные и малые количества в отдельных строках; если получатель даёт только агрегаты, доступен собственный показатель портала.

**Доставка.** Дополни белые списки `src/analytics.ts` и `SeedsMonetizationPlugin.report`, используй существующую ограниченную очередь для событий, которые должны пережить перезапуск. Снимать контекст во время действия. Локальная квитанция SDK означает принятие в очередь; до кабинета проверить отдельной доставкой. Сохранять сделанный ход и выбор языка при офлайне или сбое телеметрии. Уважать состояние разрешения аналитики каждого канала; при отключении исключать отправку и последующий слив запрещённых событий. Тестовый ключ и QA должны оставаться отдельными от production. [Очередь][journal] · [Проверка native-событий][allowlist].

## Контрольные прогоны и приёмка

| Сценарий | Что приложить и что должно получиться |
| --- | --- |
| Android, два известных клиента | Чистые контрольные установки через RuStore и NashStore, версия, способ установки, сохранённый атрибут и строка тестового отчёта. Автотест с подставленным installer дополняет проверку через настоящий клиент. |
| Один APK переслали файлом, затем обновили через другой магазин | Первый старт файла имеет неизвестный магазин и сохраняет метку артефакта. При обновлении нового Install/изменения первого магазина нет. Чистая переустановка согласно факту SDK идёт отдельно; восстановленный backup не присваивает чужой первый источник. Обновление прежнего профиля без маркера видно как legacy. |
| Численная сверка | Для набора «чистый RuStore, чистый NashStore, чистый файл, обновление уже учтённого RuStore» ожидать 3 новых Android-установки: 1 + 1 + 1 unknown. Для одного браузера на Яндексе, двух вкладок, reload и одного входа на другом подтверждённом портале — 2 новых профиля, 0 Android-установок. При отключённом хранилище новых устойчивых профилей 0. |
| Языки и прогресс | Яндекс SDK EN при языке браузера RU → английское первое поле. Открыть выбор, закрыть — 1 открытие и 0 смен. Выбрать RU в начатой задаче, перезапустить, затем вернуть Auto при SDK EN. Два осмысленных изменения, те же клетки, Undo и дата. Проверить также ручной EN → Auto при EN и `nl-NL` как неподдерживаемый язык при отсутствии других предпочтений (показываем EN). В Auto проверить каждую поддерживаемую локаль, отдельно `es-MX` и `pt-PT`. При `pt-PT` сравнить `requested_locale=pt-PT` и `ui_language=pt-BR`. Смена настроек из двух вкладок не сбрасывает звук и тему. |
| Офлайн и восстановление | Выбрать язык без сети, сделать первый ход, закрыть игру, вернуть сеть. После перезапуска язык и партия восстановлены; повтор доставки не удваивает измеряемые события. При недоступном SDK первое поле доступно, событие описывает реальный fallback, не фиктивное открытие магазина. |
| Читаемость B1 и B2 | На каждом выпускаемом языке проверить телефон 320×568, альбом 568×320, шрифт 100% и 200%, обе темы. Пройти оба курса, промах, подсказку, победу, тупик, календарь, выбор языка с TalkBack/клавиатурой и нативное напоминание при закрытой игре. На поле шириной 9 поставить 6 в клетку 9 и 4 в клетку 10 (отсчёт с единицы), остальные клетки пустые. На обоих порядках касаний пара снимается. Сравнить координаты игровой сетки до и после появления подсказки на том же шаге. Текст читается целиком, все видимые клетки принимают касания, закрытие подсказки освобождает зону. Для вьетнамского отдельно проверить диакритику, для немецкого и французского — переносы. |
| Готовность канала | Для подключённого канала показать итоговое число в **тестовом отчёте** с периодом и задержкой прибытия. Отдельно приложить результаты кода, эмулятора, настоящего клиента, кабинета и языкового плейтеста. Если доступа к кабинету/магазину ещё нет, зафиксировать конкретный непроверенный маршрут и продолжить другие каналы. |
| Равное покрытие языков | Для каждой включённой локали пройти чистый вход → самостоятельная пара → тетрадь → задача дня → настройки → результат. Сверить доступные названия кнопок, числовые формы 1/2/5/21, локализованную дату и уведомление. Список в настройках содержит только полностью подключённые локали текущей сборки. |
| Переход B1 → B2 | В B1 при системном `it-IT`, Auto и отсутствии другого подходящего сигнала показывался EN. Обновить ту же установку до B2 и запустить снова. В Auto показан IT, в ручном EN сохраняется EN. Начальная когорта сохраняет исходные значения, `language_changed` при обновлении отсутствует. |
| Понимание обучения | Дать новичку на языке проверки самостоятельно собрать пару через край строки, открыть следующую задачу тетради и найти задачу текущего дня. Отметить язык, действие и место затруднения. Скриншоты и автоматические тесты подтверждают отображение, успешное действие игрока подтверждает понимание. |
