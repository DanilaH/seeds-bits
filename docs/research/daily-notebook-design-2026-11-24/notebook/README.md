### Проверка альтернатив

В 11 конкретных задачах проверены **33 состояния**: начальное, середина сохранённого пути и состояние с двумя парами до конца. Для каждого рассмотрены все легальные непосредственные действия. Через настоящий `createSolver(5000)` получены **208 результатов: 205 FOUND, 3 NO_WIN_PROVEN, 0 UNKNOWN**. Все найденные продолжения до пустого поля воспроизведены. [Полные поля, действия и продолжения](data/fixtures.json), [solver.ts](https://github.com/DanilaH/seeds-bits/blob/df9ff5c3df8b017803e2ff924c2812a5efc530ac/src/solver.ts).

`NO_WIN_PROVEN` означает: из полученного состояния нет полной очистки одними дальнейшими снятиями пар — без «Отмены» и без Add. Настоящий bounded solver исчерпал граф этих продолжений до предела; превышение бюджета вернуло бы UNKNOWN. Add в тетрадях запрещён, а «Отмена» остаётся доступной и возвращает прежнее состояние. Статус характеризует выбранную ветку; возможность вернуться сохраняется. Лимит 5000 относится к одному вызову advice, не ко всему корпусу. Это ACTUAL SOURCE NODE, не человеческий тест и не минимальный поиск решения. В режиме без Add любая полная очистка снимает исходное число цифр попарно; длительность, число возвратов и трудность не следуют из длины сертификата.

**Что требует новых конструкций:** целенаправленные сочетания и их расположение по ходу задачи, варианты с другим характером выбора при том же объёме, новые стартовые геометрии в допустимом размере. Простая замена цифр, перестановка старых ID или большее поле сами по себе не закрывают эти цели. ## 4. Проверяемое ТЗ разработчику

### Данные и отбор

1. Подготовить две тетради по 24 новых поля, четыре страницы по шесть. Для каждой записи сохранить ID, content revision, точную доску с нулями, полный сертификат, digest, запрошенную тему и фактически подтверждённые эпизоды.
2. Пилотный диапазон: 12–32 цифры, до 54 логических клеток, действующие правила пар/сжатия, очистка без Add. На всех 48 полях проверить полный replay. Ограничения относятся к старту; нельзя уменьшать игровую клетку ради размещения.
3. Тему подтверждать состоянием до, действием и состоянием после с постоянными ID цифр. Для сжатия добавить контроль без удаления строки. Тема в одном сертификате не объявляется обязательной для всех решений.
4. Вводные поля отбирать с найденным продолжением после каждого первого легального действия. Это конкретная проверка начального выбора; гарантии всей дальнейшей партии из неё не выводить. Для нескольких поздних задач предъявить отличающиеся последствия альтернатив в ранней/средней/поздней точке. Квота проигрышных ходов не нужна.
5. Сравнить новые поля с 2400 прежними и друг с другом по точному полю и нормализации совместимых ролей цифр с сохранением позиций/нулей. Повороты/отражения не объявлять эквивалентными по правилам. Сходство промежуточных ситуаций раскрыть в отчёте; различие одного seed не считается новым семейством.

### Игровой сценарий и совместимость

Исходное состояние: есть начатая старая тетрадь, завершённый старый ID и сохранённая daily. Игрок открывает новую тематическую тетрадь, начинает задачу, делает ход, уходит, возвращается, нажимает Undo, завершает и открывает следующую. Ожидается точное поле/история/позиция, правильный номер задачи и страницы, единственная награда после durable completion. Старые задания по тем же ID сохраняют прежние поля/сертификаты; чужие сессии и права не меняются.

Если QA-подборка ссылается на прежний ID, карточка показывает его уже существующий статус. Незавершённая задача продолжает сохранённую сессию. Для завершённой сохраняется штатный повтор: новая attempt/session и обычный сброс подсказок попытки; счётчик завершённых попыток может увеличиться. Повторное решение через любой вход не создаёт второй награды семечками за этот task ID. Новые ID выделяются только новому содержимому; точная версия/миграция остаётся частью общего ТЗ совместимости.

Затрагиваемый код: `src/puzzles.ts` — каталог/разрешение ID и nextTask; `src/notebooks.ts` — описание тетради и четырёх страниц; `src/main.ts` — выбор/продолжение/следующая задача; `src/progress.ts` — валидатор новых ID и сохранение; существующие подсказка/история/награда должны корректно получать тот же task ID. `core.ts` и правила пары не требуют изменений. Пауза шести помощников сохраняется.

### Приёмка и оставшиеся UNKNOWN

- **Автоматическая:** 48 законных полных сертификатов; отсутствие случайного изменения старых полей/ID; отчёт фактических эпизодов и повторов; bounded альтернативы с FOUND/NO_WIN_PROVEN/UNKNOWN; roundtrip/Undo и одноразовая награда через все входы. Релевантный общий CI продукта, без подмены устройств моделью.
- **Экран/управление:** реальные кадры 320×568 и 390×844; текущий номер задачи/страницы, доступные действия, нижняя пара и подсказка. Непрерывный маршрут выбор → ход → возврат → Undo → завершение → следующая задача.
- **Человек:** на телефоне пройти контрастные пары и хотя бы одну полную страницу каждой темы. Зафиксировать замеченный приём, длительность, возвраты, помощь и желание продолжить. До этого названия тем, порядок задач, комфортный объём и ощущение новизны — UNKNOWN. Семечки в минуту измерять отдельно; быстрый Node replay не обосновывает изменение выплат.

Цена: исследовательский отбор уже выполнен; офлайн авторинг/метаданные и приёмка 48 новых полей — малая–средняя работа. Два входа и совместимость каталога — средняя, потому что ID участвуют в сохранениях/наградах. Переавторство 2400 старых полей значительно дороже и для пилота не нужно. Node 24 и git checkout `DanilaH/seeds-bits` с закреплённым коммитом. Скрипты читают только `git show`, проверяют Git blob и SHA256. Для настоящих исходных снимков можно задать `SEEDS_NOTEBOOK_SNAPSHOT`; проверка хешей остаётся обязательной. Продукт и исходные JSON не записываются.

SEEDS_NOTEBOOK_REPO=/absolute/path/to/seeds-bits
