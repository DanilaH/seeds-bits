## 1. Результат для игрока

Две доступные тематические тетради: **«Новые связи»**, **«Поле меняется»**, по 24 новых задачи, четыре страницы по шесть. У каждой — понятный характер и конечная цель. Новые ежедневки чередуют пять ведущих приёмов, сохраняя один вход «Сегодня» и обычный календарь. Первый ежедневный банк — 28 новых полей.

Правила пары, пустоты, края, сжатия, «Отмена» и «Подсказка» остаются действующими. «Добавить» в обоих режимах запрещено. Таймер, ограничения ошибок, новые валюты и возвращение шести приостановленных помощников не являются частью предложения. Основание паузы — [docs/help-pause-2026-11-13.md](../../help-pause-2026-11-13.md).

**Готовность означает новые поля + связный порядок + безопасную интеграцию.** Смена названия старой задачи или повторная награда за неё не выполняет это ТЗ. [48 старых эталонов](notebook/data/pilot-reference-sets.json) и [старые daily-примеры](daily/results/fixtures.json) используются для сравнения.

## 2. Пакет авторинга

Строить кандидаты офлайн существующим обратным построением либо собственными рецептами на том же ядре. Зафиксировать принятые поля и полные пути в поставляемых данных. Игроку не требуется запускать поиск на телефоне или скачивать задачу с сервера.

Для каждой записи сохранить:

| Поле паспорта | Требование |
|---|---|
| Identity | Новый стабильный task ID, content revision, точный board с нулями и digest |
| Происхождение | Версия конструктора, seed/параметры либо явный ручной рецепт |
| Полный путь | Сертификат законной полной очистки без Add, проверенный через текущее ядро |
| Ведущий приём | Один из пяти stable family IDs; остальные обнаруженные признаки отдельно |
| Подтверждение темы | Исходное состояние, префикс пути, действие, результат; постоянные ID оставшихся цифр |
| Сжатие | Контроль: та же удалённая пара, но строка ещё не сжата; различие реальных связей |
| Альтернативы | Состояние/действие/бюджет/FOUND, NO_WIN_PROVEN или UNKNOWN; полный replay для FOUND |
| Объём | Непустые цифры, логические клетки, длина сертификата; не выдавать за человеческую сложность |
| Похожие поля | Точный и нормализованный fingerprint, ближайшие совпадения, причина принятия/отклонения |
| Публикация | Редакторская позиция в тетради либо будущая календарная assignment после приёмки |

Использовать ID из [DESIGN_FEATURES.json](DESIGN_FEATURES.json). Технические паспорта не выводить игроку. Положение цифр и пустых клеток — часть структуры. Нормализация цифр должна сохранять равенство и комплементарность до 10: можно переставлять пары ролей 1/9, 2/8, 3/7, 4/6 и менять стороны внутри пары, сохраняя 5 и нули. Поворот или зеркало не объявляются эквивалентностью: правило порядка чтения требует самостоятельного replay.

Новые 76 полей сравнить друг с другом, с 2400 прежними тетрадями и с daily-v1 архивом от 2025-01 до конца предлагаемого нового окна. Точное либо только переименованное по совместимым ролям старое поле не засчитывается в 76 новых. Сходство промежуточного эпизода допустимо, но раскрывается в отчёте: повтор знакомого приёма полезен, обещание нового семейства требует нового устройства ситуации. Единый fingerprint не меняет существующую экономическую идентичность разных режимов.

## 3. Состав тетрадей

Начальный диапазон: **12–32 цифры, не более 54 логических клеток**, привычная ширина 9. Это ограничение объёма первого выпуска. Не уменьшать клетку ради размещения. Длинные необязательные задачи могут стать отдельным следующим форматом.

| Сборник / страница | Шесть новых задач должны дать | Проверенные старые эталоны |
|---|---|---|
| Новые связи / 1 | Снятие открывает линию; разные направления, простой вход | 6, 8, 89, 137, 184, 84 |
| Новые связи / 2 | Край строки в нескольких конфигурациях | 105, 133, 111, 180, 214, 241 |
| Новые связи / 3 | Чередование раскрытия и края, короткий контраст | 46, 212, 256, 119, 235, 173 |
| Новые связи / 4 | Сочетание знакомых приёмов и небольшой финал | 52, 63, 100, 148, 103, 45 |
| Поле меняется / 1 | Видимое изменение связи после удаления строки | 216, 206, 42, 64, 115, 175 |
| Поле меняется / 2 | Разное место и роль сжатия, сочетание со связями | 318, 134, 202, 310, 260, 107 |
| Поле меняется / 3 | Последствия порядка, контраст одинакового размера | 33, 78, 181, 189, 70, 73 |
| Поле меняется / 4 | Пары приёмов, короткий контраст и 1–2 финальных сочетания раскрытия, края и сжатия | 102, 161, 322, 317, 164, 171 |

Старые номера описывают исследовательскую последовательность; не копировать их под новые ID. В каждой странице первая задача — понятный вход. Для восьми вводных задач проверить продолжение после **каждого первого легального действия**: все должны дать FOUND. Это не гарантия отсутствия затруднений позже. Для остальных задач проверять сохранённый путь и паспорт приёма; на восьми контрольных задачах, по одной со страницы, дополнительно проверить все ближайшие действия в трёх закреплённых состояниях: начале, середине, перед двумя последними парами.

Не назначать квоту проигрышных ходов. Для темы порядка нужно содержательное различие последствий двух действий: конкретная разница связей общих оставшихся цифр, доступности следующего приёма либо возможности полного завершения. Различие только снятых клеток этот критерий не выполняет. Зафиксировать постоянные ID, обе ветки и объяснить влияние на следующий план. Если заявлено различие победности, нужен FOUND против NO_WIN_PROVEN, а не timeout. «Отмена» остаётся нормальным способом пересмотреть выбор.

## 4. Состав daily-банка

**28 новых задач, четыре редакторские недели.** Первые семь — 24 цифры. Для следующих 21 предлагается волна объёма 16/24/24/16/24/32/24. Дни недели и дата активации задаются после приёмки; заданные роли не становятся неизменным годовым расписанием. В четырёх неделях менять порядок приёмов, не ставить все содержательные развилки подряд и сохранять спокойные дни между сочетаниями.

Пример недели: свободная зачистка → открытие связи → край строки → передышка → порядок → сочетание → сжатие. Для каждого из пяти ведущих приёмов подготовить минимум **два причинно различающихся примера**: другое место/направление раскрытия, другой момент сжатия, другая последовательность решений. Одной замены цифр недостаточно. Три последующие недели не должны быть копиями первой с другими seed.

Все 28 пути воспроизвести. Первые альтернативы всех дней, обозначенных в авторинге как спокойные или вводные, должны дать FOUND. На двух контрольных задачах каждого ведущего приёма проверить все действия в начале, середине и перед последними двумя парами; при коротком пути одинаковое состояние не считать дважды. Для смешанной задачи хранить основной тег и дополнительные признаки, а не создавать шестое новое правило.

Бюджет первого офлайн-прогона альтернатив — 5000 состояний на один вызов solver для проверяемой ветки, как в исследовании. UNKNOWN сохраняется буквально. Если он мешает принять обещание «каждый первый ход сохраняет решение», можно адресно увеличить офлайн-бюджет с записью нового лимита либо выбрать другую задачу. Бюджет подсказки на телефоне этим не увеличивается.

**Срок банка ограничен 28 днями.** За его пределами используется прежний детерминированный daily-v1 fallback с фиксацией назначения; календарь не заканчивается и офлайн не блокируется. Следующие авторские порции добавляются до своих будущих дат. Однажды назначенное поле не заменяется позднее вышедшим банком. Контракт — [COMPATIBILITY.md](COMPATIBILITY.md).

## 6. Экранный сценарий

В существующем выборе тетрадей добавить два подписанных тематических сборника. Показать название, четыре страницы и знакомый прогресс из 24. Старые тома и фильтры доступны. Свободный выбор сохраняется; не вводить обязательную блокировку страниц, дополнительную оплату или принудительное переобучение. Уже начатая старая задача не вытесняется новым сборником.

На игровом экране короткое название сборника и номер задачи дают контекст. Технический тег, solver-статус, seed и migration version остаются вне интерфейса. Тема не раскрывает конкретную пару заранее. По завершении «Следующая» ведёт внутри того же сборника; у последней позиции вместо несуществующей №25 предлагается вернуться к тетради. Если №24 решена раньше остальных, показывать фактический done/24 и доступные незавершённые задачи. Тетрадь завершена только при 24/24; тогда показать её завершённую страницу и выбор других тетрадей. Отдельная новая выплата за тетрадь не вводится.

В daily сохранить обычный маршрут Сегодня → поле → результат → календарь. Даты старых эталонов не используются как новые назначения. Дату и переход через полночь проверять по действующему локальному календарю приложения. Нижняя пара, Hint/Undo, возврат и следующий шаг должны оставаться доступны на 320×568 и 390×844; не обещать, что 54 клетки автоматически помещаются на любом устройстве.

## 8. Приёмка, поставка и следующий шаг

**Данные:** 48 + 28 новых полей; полный replay 76/76; диапазоны объёма; паспорта пяти приёмов; уникальность и нормализованные повторы; результаты указанных альтернатив; отклонённые кандидаты с причиной. Смена seed сама по себе не считается приёмкой разнообразия.

**Совместимость:** все сценарии C01–C12 из COMPATIBILITY; старые поля/ID/порядок массива неизменны; единичная выплата, сохранение истории/подсказок/прав; fallback и полноценная работа офлайн. Необходимо содержательное покрытие сохранений, календаря и UI, а не тест, повторяющий таблицу метаданных.

**Экран:** реальные кадры и непрерывные записи на двух размерах: старая сессия → новый сборник → ход → закрытие/возврат → Undo → Hint → завершение → следующая задача; daily через полночь и офлайн. Запись браузера и Android-эмулятора маркировать отдельно от физического телефона.

**Человек — пока UNKNOWN:** пройти на телефоне контролируемую пару одного размера и по одной полной странице двух тем; семь daily постоянного объёма сравнить с закреплённой заранее текущей неделей. Записать длительность, Undo, Hint, объяснение замеченного приёма и добровольное продолжение. Не подсказывать ожидаемое впечатление перед игрой. Небольшая разведочная проверка корректирует порядок/размеры и не доказывает D1 или статистический рост. Она не блокирует офлайн-авторинг и работу над совместимостью.

**Выплаты:** текущая формула `min(24,max(4,ceil(pairCount/4)*2))`; тетрадь получает награду один раз за task ID, daily — один раз за calendarDay независимо от версии поля. Для daily 16/24/32 это 4/6/8 семечек. При нынешней единственной версии daily день и ID соответствуют друг другу; новая версия сохраняет прежнее право на одну выплату. Серия даёт дополнительные подсказки в существующий wallet, это не семечки. Сохранить выплаты, отдельно измерить время и семечки в минуту. Изменение экономики требует собственного задания, не выводится из скорости Node replay.

Поставить отдельный продуктовый PR с банком, интеграцией, воспроизводимым отчётом и точным паспортом APK. Исследователь после PR сравнивает diff и проверки, обновляет ADOPTION_LEDGER; наличие кода, телефон и аудитория закрываются раздельно. Нынешний docs-пакет ничего из этого не объявляет выполненным.

**Порядок и цена:** (1) авторинг 76 и паспорта — малая–средняя; (2) identity/календарь/сохранения — средняя, можно вести параллельно; (3) интеграция двух сборников и существующего daily — малая–средняя после resolver; (4) адресная приёмка и фиксация будущих дат. Следующие темы и расширенные конструкции — отдельные порции после первого банка, с условиями возврата в DESIGN_FEATURES. **KIT IMPACT — REUSE / CANDIDATE.**
