# Ежедневные задачи: репертуар, контрастная неделя и расширение банка

24 ноября 2026. **«Семечки», собственный режим ежедневной задачи.** Исследовательское предложение на `df9ff5c3df8b017803e2ff924c2812a5efc530ac`. Новых наблюдений оригиналов Number Match Easybrain/NADO или Number Tiles нет. Игровой код, даты, сохранения, награды и правила не изменялись.

## Предложение

Дать каждой новой ежедневной задаче ведущий приём: свободная зачистка, открытие связи, переход через край строки, изменение связей при сжатии или выбор порядка. Собрать из них **короткую авторскую неделю**, затем расширять банк вариантами этих постановок и их сочетаниями. Для первого выпуска достаточно четырёх недель — 28 новых задач; это рабочий объём пилота, не статистический норматив и не обещание годового запаса.

В текущих ежедневках уже есть нужный материал. Подборка ниже показывает отличия при одинаковых **24 цифрах / 12 снятиях**. Сначала стоит проверить характер задач при постоянном объёме. После этого можно испытать отдельную волну длины **16 / 24 / 24 / 16 / 24 / 32 / 24**. Польза такой недели для игрока — гипотеза до телефона; время решения из количества цифр не выводится.

**Даты в примерах — происхождение полей. Они не переназначаются на дни новой недели.** Все текущие `daily-v1-YYYY-MM-DD` остаются прежними. Старые поля служат проверяемыми образцами для авторинга; выдавать их как новые задания с повторной наградой не предлагается. Политику нового ID/даты включения описывает общий план совместимости.

## Что проверено

[source-manifest.json](source-manifest.json) фиксирует Git blob и SHA256 исполняемых исходников. [research.mjs](research.mjs) исполняет фактические `daily()`, ядро, измеритель и bounded solver на Node v24.22.3; типы и импорт модулей преобразуются без изменения игровой логики.

- Все **365** `daily()` календарного 2026 года созданы исходным кодом; их записанные пути до пустого поля воспроизведены. Это вычисленный календарный срез, включая будущие на дату исследования дни, а не сеансы пользователей.
- Для всех 365 посчитаны профиль выбранного пути и три прозрачных порядка снятия без Add. Провал такого порядка остаётся `UNKNOWN`, не объявляется неразрешимостью поля.
- Выбраны **12** исследовательских примеров: семь для недели одинакового объёма, один контроль сжатия, три примера другой длины и один отклонённый кандидат. Отбор сделан после просмотра профилей: это exploratory-набор, не контрольная выборка для оценки качества всей выдачи.
- В шести задачах исследованы все доступные пары в трёх состояниях выбранного пути: до хода 1, после 5 снятий и после 9 снятий. **18 состояний, 195 действий: 193 FOUND, 2 NO_WIN_PROVEN, 0 UNKNOWN** при бюджете 5000 состояний на ветку. Для FOUND сохранено и воспроизведено полное продолжение.
- Оба NO_WIN_PROVEN дополнительно подтверждены закрытием всего достижимого графа через то же игровое ядро: 8 состояний / 12 переходов и 3940 состояний / 20 176 переходов. Пустое поле недостижимо из этих двух состояний только последующими снятиями пар — без использования «Отмены» и без Add.

**Граница NO_WIN_PROVEN:** проверяется продолжение из данного состояния только снятиями пар. «Отмена», перезапуск и Add в этот граф не входят. В обычной ежедневной задаче Undo остаётся доступным: после рассмотренного неудачного хода можно вернуться к сохранённой развилке и выбрать другое продолжение. Этот статус не означает безвозвратный проигрыш партии.

## 1. Пять постановок для расширения

Названия — наши рабочие теги авторинга, их не обязательно показывать игроку. Теги пересекаются; у задачи выбирается один ведущий приём и сохраняются остальные фактически обнаруженные признаки.

| Стабильный localResearchId | Что делает игрок | Проверяемое содержание | Как расширять |
|---|---|---|---|
| `seeds-daily-flow` | Замечает несколько удобных пар и быстро очищает части поля | Несколько проверенных стартовых продолжений; мало обязательных перестроений на выбранном пути | Менять расположение небольших групп и направления, оставляя короткую приятную зачистку. Не оценивать её только числом стартовых пар. |
| `seeds-daily-reveal` | Снимает пару и замечает новую связь через открывшийся промежуток | Для двух конкретных оставшихся цифр ребра не было до хода, после него оно есть; ID цифр прослеживаются через сжатие | Цепочки из двух раскрытий; боковое вместо вертикального раскрытия; два различных полезных открытия. Каждую цепочку проверять до конца. |
| `seeds-daily-reading` | Использует разрешённый переход по порядку чтения через край строки | В сохранённом эпизоде `checkPair.kind === reading`, а обычного прямого направления недостаточно | Один переход в короткой задаче, два перехода в разных местах, сочетание с освободившимся промежутком. Это существующее правило, не новая механика. |
| `seeds-daily-compression` | Очищает ряд и пересматривает появившиеся связи | Сравнение поля с обнулённой парой до удаления ряда и реально сжатого поля показывает созданную/потерянную связь между теми же цифрами | Заранее подготовленный полезный сдвиг ряда; раскрытие после одного сдвига; комбинация с чтением края. Не считать простую перенумерацию клеток новизной. |
| `seeds-daily-order` | Сравнивает последствия доступных снятий | Зафиксированные ветки с разным исходом либо разными подтверждёнными последствиями; легальность отдельно от победности | Небольшие развилки после спокойного входа. Доказанный невыигрышный ход не является обязательной нормой семейства; не максимизировать долю веток, требующих возврата. Сохраняются нынешние Undo/Hint. |

Уже найденные эпизоды показывают, что все пять постановок совместимы с нынешними правилами. Не требуются новые цифры, блокеры, таймер, Add в ежедневках, отдельная валюта или включение приостановленных помощников. Процент каждого семейства и финальные названия пока не откалиброваны.

### Почему одного тега мало

Первым образцом «перехода через край» был день **16.10.2026**. В его пути действительно четыре reading-хода, но стартовое снятие `(5,15)` ведёт в доказанно невыигрышную ветку. Для спокойного ознакомительного дня этот кандидат отклонён. В примере **21.10.2026** все проверенные 21 стартовая, 9 средних и 2 поздних альтернативы имеют выигрышное продолжение. Это ограниченная приёмка конкретного образца, а не доказательство всех его достижимых состояний. [Альтернативы и исходные поля](results/choice-probes.json).

Значит, авторинг должен фиксировать **намеренный приём + фактический эпизод + последствия выбора**. Четыре счётчика в паспорте ещё не дают готовый качественный день.

## 2. Неделя постоянного объёма для первой проверки

Все семь примеров содержат 24 цифры и решаются за 12 снятий без Add. Поле занимает 36 или 45 логических клеток; пустоты остаются частью геометрии. Дни недели ниже — предлагаемая роль в QA-подборке, не новые календарные назначения.

| Роль | Образец текущего daily | Начальных пар | Через пустоты / reading в пути | Новых связей / изменений от сжатия | Ожидаемое впечатление — гипотеза |
|---|---|---:|---:|---:|---|
| Пн — свободная зачистка | 25.02.2026 | 24 | 3 / 1 | 4 / 0 | Быстрый спокойный вход |
| Вт — открывающиеся связи | 17.06.2026 | 19 | 6 / 1 | 9 / 0 | Замечаю, что мой ход открыл следующую пару |
| Ср — край строки | 21.10.2026 | 21 | 6 / 3 | 7 / 0 | Переключаю способ поиска пары |
| Чт — передышка | 03.02.2026 | 18 | 4 / 2 | 4 / 0 | Короткий понятный рисунок после двух разных задач |
| Пт — порядок | 06.03.2026 | 14 | 10 / 4 | 9 / 0 | В середине приходится проверить последствия выбора |
| Сб — сочетание | 12.05.2026 | 19 | 5 / 1 | 12 / 3 | Несколько приёмов в одной небольшой задаче |
| Вс — сжатие | 30.03.2026 | 17 | 6 / 2 | 13 / 4 | После удаления ряда замечаю новые связи |

Числа описывают выбранные сертификаты. «Новая связь» определяется по стабильным ID цифр, сохраняя нули и границы строк. «Изменения от сжатия» включают появившиеся и исчезнувшие связи после физического удаления пустого ряда; это не число анимаций сжатия. [Точные определения измерителя](https://github.com/DanilaH/seeds-bits/blob/df9ff5c3df8b017803e2ff924c2812a5efc530ac/src/classic-profile.ts#L40-L109).

Ритм разной длины — отдельная следующая гипотеза. Для него приложены короткие образцы 11.03 и 09.06 по 16 цифр и комбинированный 16.05 на 32 цифры. Если одновременно поменять длину и устройство недели, нельзя приписывать результат только разнообразию приёмов. Не привязывать тяжёлый день к субботе навсегда: конкретная недельная схема подлежит проверке.

## 3. Проверяемые эпизоды для разработчика

Координаты ниже — индексы с нуля в массиве соответствующего состояния, ширина 9. Префиксы, полные начальные поля и окончания сохранены в `fixtures.json`; прямое использование индексов стартового поля после сжатия запрещено.

### A. Раскрытие пары без сжатия

Источник: `daily-v1-2026-06-17`, после первых двух ходов сохранённого пути.

- Поле до действия: `100000080100806620910020002204400010520000925`.
- Действие: снять индексы **34,42**, значения **1+9**.
- После: `100000080100806620910020002204400000520000025`.
- Ожидаемо: появляются пары **16,43** и **37,43**; эти связи отсутствовали до хода. Пустая строка не удаляется. Полный оставшийся путь законен.
- Задание авторингу: подготовить ещё один короткий пример этого приёма с другой геометрией/положением раскрытия, не ограничиваясь переименованием цифр. Приёмка — те же конкретные before/action/after и законный полный путь.

### B. Переход через край

Источник: `daily-v1-2026-10-21`, после семи снятий.

- Действие: снять **35,37**, значения **3+3**. Индекс 35 — конец четвёртого ряда, 37 — второй столбец пятого; 36 пуст.
- `checkPair()` подтверждает **reading**, обычная прямая связь не используется.
- После удаления остаются 8 цифр, три доступные пары; сохранённое продолжение очищает поле.
- Приёмка: подпись/подсказка использует текущее правило края; поле и сертификат не проходят через «удобный» поворот или отражение без нового replay.

### C. Реальное изменение геометрии при сжатии

Источник: `daily-v1-2026-03-30`, после шести снятий.

- До: `060006600000000050404030007000006000003005007`.
- Действие: снять **5,32**, значения **6+6**. Четвёртый ряд опустевает.
- После: `060000600000000050404030007003005007` — 36 вместо 45 клеток.
- Связь между исходными ID **17 и 42** появляется именно из-за сжатия: после него это пара **16,32**. Связь между ID **23 и 39**, существовавшая в поле с дырками до сжатия, исчезает.
- Сравнение ведётся между теми же оставшимися цифрами. Это подтверждает смену геометрии, а не ложную новизну из-за новых индексов.

Контроль — `daily-v1-2026-09-18`: тоже **24 цифры, 45 клеток, 17 стартовых пар, 6 gap и 2 reading** в выбранном пути, но **7** новых связей и **0** изменений связей от сжатия против **13 / 4** у 30.03. Числа и стартовый объём не исчерпывают устройство задачи. Это не доказательство, что один день человеку труднее другого.

### D. Выбор порядка с подтверждёнными последствиями

Источник: `daily-v1-2026-03-06`, после пяти снятий.

- До: `420060000006013601010000090009329000`.
- Доступно восемь пар. Снятие **13,29** (1+9) имеет проверенное выигрышное продолжение.
- Снятие **19,25** (1+9) законно, но полная очистка после него невозможна только последующими снятиями пар: весь такой достижимый граф имеет 8 состояний и 12 переходов; единственный конечный остаток непустой. Нынешняя «Отмена» остаётся доступной: один возврат восстанавливает показанную развилку, после чего можно выбрать проверенный ход **13,29**. Это не безвозвратный исход партии.
- На старте этой же задачи все 14 легальных первых действий имеют найденное решение. Развилка появляется в середине выбранного пути.
- Ожидание UI — нынешние Undo/Hint и обычная обратная связь. Не добавлять автоматический запрет законной пары, наказание, платный выход или новую помощь. На телефоне проверить, понимает ли игрок причину затруднения и помогает ли возврат без раздражения.

Все точные состояния и соответствующие выигрывающие окончания — в [choice-probes.json](results/choice-probes.json); компактные визуально значимые эпизоды — в [episodes.json](results/episodes.json).

## 4. Конкретный пакет разработчику

### Первый этап: расширить банк содержанием

1. Подготовить **28 новых небольших постановок** на действующих правилах, с пятью ведущими приёмами выше. Для первой сравнительной недели использовать одинаковые 24 цифры; остальные примеры могут покрывать 16/24/32 после отдельного выбора ритма. Число 28 означает четыре недели для просмотра, а не приёмку годовой выдачи.
2. Строить поля офлайн существующим reverse-конструктором или собственными проверяемыми конструктивными рецептами. Сохранять seed/параметры, точные board/proof, замысел, фактически наблюдаемый эпизод и профиль. `makePuzzle()` уже пригоден для дешёвого поиска кандидатов; при нехватке примеров расширять **геометрию конструкций**, а не бесконечно крутить веса по прежнему узкому набору.
3. Для каждой ведущей постановки предъявить как минимум два отличающихся причинных эпизода: другое место/направление связи, другая роль сжатия, другая последовательность открытий. Одно переименование совместимых цифр не считается новым содержанием. Не использовать произвольные D4-повороты/зеркала как гарантированно эквивалентные из-за reading-правила.
4. Автоматически проиграть все 28 сертификатов, проверить завершение без Add и исходные награды. На контрольных задачах каждого приёма проверить первые и выбранные средние/поздние действия с явным бюджетом. Для спокойного вводного дня не принимать известный невыигрышный первый ход; `UNKNOWN` не маркировать как безопасный или как ловушку. Это ограниченный QA-критерий пилота, не поиск полной уникальности решения.
5. Сохранить перечень отклонённых кандидатов и причины. Не подменять неудавшуюся постановку обычным случайным полем под тем же названием. Слабый/неподтверждённый профиль — явно обычная резервная задача либо отказ сборки офлайн-банка, по выбранному контракту.

### Второй этап: дать этому ритм

Сначала показать семь постоянных по объёму примеров без подсказки, какое впечатление «нужно» получить. Записать фактическую длительность, возвраты, подсказки, объяснение обнаруженного приёма и желание открыть следующую задачу. Сравнить с заранее закреплённой текущей неделей; не выбирать контроль задним числом под красивый результат. В небольшой разведочной группе не делать заявлений про удержание или статистический рост.

После этого проверить волну длины и обычную дату/архив через общий план совместимости. Один привычный вход «Сегодня», существующий календарь, серия и месячный трофей уже дают режиму структуру. Для первого расширения не нужны дополнительные экраны выбора правил, таймеры или обязательная новая метаигра.

| `src/puzzles.ts:124–160`, `src/progress.ts:29–35`, `src/daily-run.ts` | Будущая маршрутизация новой версии/даты должна сохранять старые assignments, today-отличие от архива, progress/Undo и уникальность награды. Точный migration contract — общий план. |
| `src/main.ts` — вход в задачу, календарь, result/return | Проверить существующие переходы на новой записи, без новой обязательной обучающей преграды. |
| `tests/puzzles.test.ts` и текущие daily/save проверки | Replay всего нового маленького банка + старые фиксированные даты/сохранения; это содержательная проверка новой базы. |

**Цена:** низкая для профилирования/подбора из существующего конструктора; средняя для авторинга 28 устойчиво различающихся задач и совместимого выпуска. Отдельные новые правила, экономическая прогрессия, live director и серверный подбор существенно увеличили бы стоимость, а данными этого прохода не обоснованы.

## 5. Как расширять после первого банка

Расширение измерять количеством действительно новых **постановок и сочетаний**, а не только числом seed. Для каждого приёма последовательно добавлять: другое пространственное расположение → другой момент раскрытия → два связанных раскрытия → комбинация со сжатием/краем. Новая неделя комбинирует проверенные задачи; она не обязана повторять один вечный порядок понедельник–воскресенье.

Если пользователи различают только длину, сначала пересмотреть постановки и их видимость. Если контраст замечают, но отдельный день раздражает, исправлять конкретный образец и возврат, не снижать скрыто сложность всего режима. Отдельный вопрос — достаточна ли нынешняя награда относительно времени; до телефонных измерений выплаты сохраняются.

**KIT IMPACT — REUSE:** сохранены уровни доказательства, стабильные ID цифр, различение объёма/выбора и исходов bounded search. Новых `sourceFeatureId` оригинальных игр в этом исследовании нет; перечисленные `seeds-daily-*` — локальные исследовательские предложения.

## Воспроизведение

Нужны Node 24 и Git checkout с точным `df9ff5c3df8b017803e2ff924c2812a5efc530ac`. Из корня checkout:

```bash
SEEDS_RESEARCH_REPO=/absolute/path/to/seeds-bits \
SEEDS_DAILY_OUTPUT=/tmp/seeds-daily-design-results \
node /absolute/path/to/daily/research.mjs
```

По умолчанию источники читаются через `git show`, результаты пишутся в `test-results/daily-content-design`. Для уже выгруженного точного снимка предусмотрен `SEEDS_DAILY_SNAPSHOT`; независимо от способа чтения каждый исполняемый файл проверяется по Git blob и SHA256. Выполненный проход использовал этот snapshot-режим, без нового полного clone. Данные приложения не перезаписываются. Повтор не зависит от текущего календарного дня: год и даты выборки закреплены в скрипте.
