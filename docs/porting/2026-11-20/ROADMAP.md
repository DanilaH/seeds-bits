# Классика «Семечек». Что проверить перед изменением плюса

20 ноября 2026. Игровая база `feat/monetization-assists-20261113`, `7fee610c981eb5f9ac77cbccf4a9c7b5cb32877b`. [Реестр переноса](../ADOPTION_LEDGER.json) · [источники Easybrain и NADO](https://github.com/DanilaH/mini-games-kit/blob/a0bc409a34033ea47501a7d59966e690e9b647cd/research/games/seeds/2026-11-20-classic-add/README.md).

## Что видит игрок сейчас

В классике при хотя бы одной легальной паре «Добавить» сообщает, что остались пары. При нуле доступных пар включается «Добавить», а подсказка выключается. Счётчик на кнопке показывает **сколько цифр допишется**. Отдельного запаса использований нет. Сохранённая партия с пятью прошлыми добавлениями принимает шестое и седьмое. При пустом бюджете подсказок предложение появляется, если на поле есть доступная неоплаченная пара. В проверенном сценарии игрок закрыл предложение без просмотра, затем попал в тупик. Списания и запросов показа при тупике не было. Тест использует имитацию готового рекламного моста.

Для ежедневной задачи и тетради действуют другие правила. При полном поле без возможности расширения классика также имеет технический предел в 1800 ячеек. Его обработчик предлагает отмену или новую партию.

## Воспроизводимая проблема обратной связи

На обычной сложности (seed 3) есть последовательность из десяти легальных пар. После неё на поле восемь цифр и ноль пар. Первое «Добавить» удваивает их число до шестнадцати, при этом игрок снова видит ту же инструкцию, а лампочка по-прежнему выключена. Второе добавление доводит число цифр до 32 и открывает 18 пар. [Начальное поле, индексы ходов и обе доски](double-add.json) · [проверка через игровые кнопки](../../../e2e/porting-classic-add.spec.ts).

Для проверки частоты в модели воспроизвели 512 различных стартов на обычной сложности (seed 0…511). На каждом использовали три стратегии. До первого добавления всегда снимали легальную пару. Знаменатель в четвёртой колонке — партии конкретной стратегии, дошедшие до первого тупика.

| Выбор пары | Очистили поле без добавления | Первый тупик | Первое добавление оставило ноль пар | После двух подряд всё ещё ноль |
| --- | ---: | ---: | ---: | ---: |
| Первая по порядку ядра | 86 | 426 | 15/426 (3,52%) | 0/15 |
| Последняя | 68 | 444 | 14/444 (3,15%) | 0/14 |
| Псевдослучайная с воспроизводимым seed | 66 | 446 | 14/446 (3,14%) | 0/14 |

На других уровнях сложности, при другой стратегии и в более поздних тупиках результат может отличаться. Данных о частоте у игроков и влиянии на удержание нет. [Скрипт](sample-classic.mjs) · [числа из прогона](first-add-sample.json).

## Очерёдность

1. **Можно отдавать разработчику как предложение по UX.** Критерий — после успешного добавления на непустом поле без новых пар статус явно объясняет, что только что произошло и какое действие доступно. Например, «Добавлено 8 цифр. Пар пока нет — можно добавить ещё 16». Получать факты из нового состояния доски и того же набора пар, по которому отрисованы кнопки. При достижении технического предела подсказать отмену/новую игру. Прогнать поле seed 3, случай с парой сразу после Add, состояние после Undo и короткую задачу. Затрагиваются игровой обработчик add() и вывод статуса в src/main.ts. Существующий сценарий фиксирует правила, а для изменения текста понадобится отдельное ожидание статуса после первого Add.
2. **Проверить решения игрока в оригиналах.** Сначала Easybrain — ранний плюс, цена, возврат запаса после отмены и сообщение при последнем плюсе. Затем на NADO воспроизвести те же состояния, в том числе проигрыш со второго этапа. Для подсказок отдельно записать запас до/после, доступность кнопки, предложение видео, отказ и поведение офлайн. Варианты Easybrain по молотку, VIP и событиям имеют отдельные строки в реестре.
3. **Решение владельца по правилам.** Если удастся подтвердить полезный сценарий для раннего плюса или лимита, оформить отдельный playtest-пакет. Определить расход/возврат при Undo, поведение старых сохранений и тупик, где один плюс сам не даёт пары. В обычном профиле все шесть прежних экспериментов остаются на паузе по решению владельца. Выход в коммерческий эксперимент требует отдельного продуктового задания.

## Проверки

Из корня игры после установки зафиксированных зависимостей:

```sh
npx vitest run tests/core.test.ts tests/hint-budget.test.ts
npx playwright test e2e/porting-classic-add.spec.ts
node docs/porting/2026-11-20/sample-classic.mjs
```

Локально прошли 13 unit-тестов, два новых Playwright-сценария и существующий сценарий adds only when stuck. Эталонное сравнение реестров проверяется скриптом tools/verify-reference-porting.py из кита. Автоматический браузерный тест сравнения использовал Chromium headless shell при ширине 390 CSS px. Физические Android-нажатия в оригиналах остаются открытой частью исследования.
