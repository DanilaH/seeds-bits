# Компактное размещение баннера

Запрос пользователя: большой пустой низ на экране тетради №91, более компактная реклама и управление ближе к низу во всех ориентациях.

## Изменение

- Вместо `BannerAdSize.sticky(context, width)` используется `BannerAdSize.inline(context, width, 50)`: ширина выбирается по реальному свободному месту, максимальная высота запрашивается у SDK в **50 dp**. Это ограничение запрашиваемого креатива, а не обрезание большого баннера.
- Высота из SDK переводится из физических пикселей в CSS-пиксели с фактическим масштабом WebView. Поэтому резерв может отличаться от 50 CSS px при другом масштабе. Исправлен прежний запрет на CSS-высоту менее 45 px: реальную достаточность проверяет native-код.
- Нативный контейнер имеет высоту SDK-креатива и прижат к нижнему краю выделенной области. Слишком маленькая область скрывает баннер до исправления геометрии; обрезания нет. Реальное изменение ширины пересоздаёт баннер сразу, а ошибка загрузки по-прежнему соблюдает минутный интервал повторов.
- Начальный web-резерв сокращён с 72/60 до 50 CSS px, служебный зазор — до 12 px. Между footer и баннером остаётся 8 px; внутренняя нижняя подкладка кнопок — 4 px. Повторный системный inset в footer удалён: при рекламе его учитывает рекламная полоса, без рекламы — край игрового экрана.
- Низкий резерв остаётся стабильным и при загрузке/отсутствии креатива, чтобы кнопки не перемещались под пальцем. Реклама скрыта в меню и обучении, а системная панель и вырезы учитываются по данным Android/Capacitor.

## Проверка

В native harness добавлены сценарии ограничения 50 dp, различающихся density и масштаба WebView, нижнего выравнивания, слишком малой области, восстановления без нового запроса, изменения ширины и повторов после ошибки. Это state/geometry-проверки на doubles; реальный API дополнительно проверяется компиляцией Android с Mobile Ads SDK 8.5.0.

Браузерные сценарии используют реальное поле `book-v1-2161` — тетрадь 91, задача 1, 212 цифр. Проверяются телефон 320/390 px, короткий и обычный landscape, планшет, обе темы, крупный текст, однократный нижний inset с рекламой и без неё, CSS-высоты 40/80/50 px. Записи сравнивают текущий интерфейс с исходником `e0483c8`; рекламная область на размеченных кадрах — явный макет, не доказательство живой рекламы.

Основание API: [адаптивный inline](https://ads.yandex.com/helpcenter/en/dev/android/adaptive-inline-banner), [переименование методов в SDK 8](https://ads.yandex.com/helpcenter/en/dev/android/release/8-0-0-migration). Визуальные результаты и APK фиксируются после CI.
