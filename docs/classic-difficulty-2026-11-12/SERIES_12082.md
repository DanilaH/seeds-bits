## GA-01. История выбранных полей

После выдачи сохраняются фактический рецепт и нормализованная форма поля в одном месте проверенного пути. Для маршрута с «Добавить» берётся состояние перед первым добавлением. Для остальных маршрутов берётся середина очистки. Пустоты и координаты сохраняются. Допускается переименование пар взаимодополняющих цифр с сохранением отношений равенства и суммы 10.

Отбор сравнивает до четырёх последних сценариев этой сложности. Повтор фактического рецепта и близкая центральная форма уменьшают оценку кандидата. Самый большой штраф получает точный недавний повтор формы. Для близкого совпадения нужно согласие не менее 80% по объединению занятых позиций при одинаковых длине и этапе. Один рецепт может выиграть подряд, если его кандидат выходит вперёд по сумме оценок. Старое необязательное поле предпочтений не трактуется как история фактических рецептов. [Код отбора](../../src/classic-generator.ts) · [Измеритель формы](../../src/classic-profile.ts).

У 18 и 28 один основной способ построения, `shuffle`. Их варианты отличаются формой и ходами. У 45 и 81 частота точных центральных повторов за четыре партии снизилась, а повтор одного рецепта подряд участился. Один плотный рецепт может дать разные формы перед добавлением. Счёт близких совпадений в этих сериях равен счёту точных. Восемь последних стартовых полей и их нормализованная структура остались без повторов во всех проверенных сериях.

Все **18 408** строк содержат законный путь до пустого поля. Из них 16 000 свежих раздач, 2 400 серийных и восемь принудительных запасных раздач. В каждой серии следующее поле также сверялось после чтения сохранения. Лёгкая проходилась первой доступной парой. Состав Обычной и полная плотность 45 и 81 проверены для каждой раздачи. Для старых запасных полей `requestedStyle` воспроизводит историческое значение `open`, которое старый API возвращал при fallback.

### Как повторить

Node 24, checkout с обеими ревизиями. По умолчанию результат записывается в `test-results/classic-series/`.

```bash
node scripts/classic-series.mjs \
  --before 7f8ac0e05a338d4101d10f680720343b6881ba9a \
  --after eae2bcbeaaa1a5c76872dddc7a7f79844988b60e \
  --fresh 30000:30999 --control 40000:40999 \
  --series-seeds 12081,42081,52081 --series-count 100
```

- `deals.jsonl.gz` содержит seed на входе и выходе, SHA-256 снимка состояния, запрошенный профиль, фактический рецепт, исходное поле, форму, весь путь, диагностику, лимиты и fallback.
- `summary.json` содержит распределения по уровню, диапазону и серии, таблицы запрошенных и выданных рецептов и частоты повторов. Для серий есть отдельный срез после заполнения истории.
- `audit-29-30.json` содержит оба точных воспроизведения из таблицы. `manifest.json` фиксирует команду, Node, исходные Git blob и SHA-256 результатов.
