# Handoff — продуктовый аудит «Семечек»

Приложение не опубликовано в RuStore и не отправлено на модерацию. В этом задании публикация, модерация и изменение production-рекламных настроек не выполнялись.

Кандидат **1.1.2**. Проверяемый исходник приложения: `160da8c79fd013f25a64607b7338ed6a65131942`. Ветка `qa/product-audit-20261111`, [PR #2](https://github.com/DanilaH/seeds-bits/pull/2). Коммит с материалами следует за этим исходником и не меняет runtime; точные SHA приложения и источников записей закреплены в [source-proof.json](source-proof.json).

[Полный аудит с доказательствами и гипотезами](../PRODUCT_AUDIT_2026-11-11.md) · [скриншоты, сравнения и GIF](README.md) · [машиночитаемая приёмка](acceptance.json).

## Что изменилось

- Завершение попытки и награды попадают в AppMetrica после успешного сохранения результата. Ограниченный журнал переживает повтор/перезапуск и сохраняет `attempt`, `event_id`, исходное время и запуск. Восстановленная очередь также ждёт подтверждённой записи, а не доверяет одному чтению process cache Android.
- Ошибка планирования напоминания больше не маскируется под отказ уже завершённой записи прогресса. Повторная доставка rewarded receipt не начисляет подсказки дважды.
- Разделены release/preview, версия и сборка, ad test mode. Preview по умолчанию не использует production-аналитику; необязательный `APPMETRICA_QA_API_KEY` предназначен для отдельного QA-счётчика. Появились сохраняемые ранние milestones и разделение fresh/legacy. Семантика прежних `game_open` и `game_start` сохранена и описана.
- После короткого обучения можно сразу выбрать маленькую задачу; первый самостоятельный результат становится доступнее. В уроке упомянут переход через край строки, подсказка объясняет конкретную пару, завершение страницы ведёт к «Следующей странице».
- Исправлены перенос действий при реальном тексте 150% в портрете и поздняя перезапись сводных web-настроек двумя вкладками. Короткий landscape сохраняет компактные действия. Правила, набор задач, награды и частота рекламы сохранены.

## Проверки

Фактические результаты и границы каждого исходника закреплены в `acceptance.json`. Основной прогон: [Product audit 43032671115](https://github.com/DanilaH/seeds-bits/actions/runs/43032671115); обычные PR checks после исправления установки браузера: [43036052046](https://github.com/DanilaH/seeds-bits/actions/runs/43036052046). `2434401` меняет только workflow, код приложения совпадает с `160da8c`.

Обычные PR checks `43036052046` прошли целиком: **61 unit + 2 model, 15 integration, 167 E2E**, web/Yandex builds и Android preview. Product browser дополнительно прошёл **30** повторов строгого cross-tab сценария, **38 / 221** обзорных состояний и **4 / 72** последовательных записей. Измеренных horizontal/text overflow и page errors в матрице нет.

Unit, модель compact history, browser integration и E2E проверяют ошибки записи, reload/restore, повторы событий и наград, режимы, рекламу, старые сохранения и геометрию. Дополнительный исходный строгий cross-tab сценарий повторяется 30 раз; его assertions не ослаблялись. Java harness компилирует production-мосты с управляемыми doubles: **24** сценария monetization/persistence и **16** вибрации прошли. Это не доказательство работы внешнего SDK или физического мотора.

Матрица интерфейса включает телефоны 320/360/390 px, короткие горизонтальные экраны, планшеты, обе темы, реальные увеличенные шрифты, длинные поля, клавиатуру, reduced motion, состояния наград и рекламных мест. Последовательные записи начинаются с чистого контекста и проходят первую страницу, дейлик и восстановление. Решения известны сценарию: это автоматический прогон настоящего UI, **не человеческий плейтест и не измерение скорости/удовольствия**. Поздние состояния коллекции в обзорной матрице задаются fixtures.

Предыдущая успешная изолированная нативная приёмка — [43029903310](https://github.com/DanilaH/seeds-bits/actions/runs/43029903310), runtime `c3b4ebf`, Android 35, release payload, временная CI-подпись. Native Java совпадает с окончательным исходником; JS окончательного исходника дополнительно ждёт успешной записи при восстановлении журнала. Это изменение проверено browser fault injection, но предыдущая APK-приёмка не переименовывается в проверку окончательного APK. Проверяется clean install, отказ/выдача notification permission, настройки, крупный текст, поворот, закрытие процесса и восстановление. Upgrade — настоящий `adb install -r` с предварительной 1.1.0/1100024 с тем же временным сертификатом: доска классики, undo, hints, тетрадь и тема. Это не production-сертификат и не физический телефон.

**Оставшийся блокер финального emulator-прогона:** обе попытки запуска для `160da8c` остановились на DNS Ubuntu во время установки OCR, до установки приложения. Результаты последнего APK в native UI/upgrade не получены. [Сбой CI и границы](evidence/ci-infrastructure.json), [предыдущая приёмка](evidence/previous-native-ux.json), [smoke](evidence/previous-native-smoke.json), [upgrade](evidence/previous-native-upgrade.json). Обычный web CI также сначала не установил Chromium; `2434401` убирает лишний apt update, сохраняя штатный Chromium, его startup validation и все assertions.

## Известная ошибка QA и данные

Ранний нативный UX-этап был ошибочно назван офлайновым: сеть оставалась доступна и на кадрах есть настоящая реклама. Ошибка зафиксирована, не скрыта и не считается успешной офлайновой приёмкой. Возможная доставка AppMetrica не подтверждена без кабинета. Нужно исключить **1.1.2 / 1102004–1102014** из аналитики игроков по SDK `app_build_number` или custom `app_build`: [точный список](analytics-quarantine.json). Данные в кабинете не удалялись; старые исследовательские CSV этим не объявляются QA-трафиком.

Финальный эмулятор ограничен host firewall IPv4/IPv6 до boot/первой установки, отдельной группой процесса QEMU, проверкой отказа исходящего запроса, Wi-Fi/data off и закрытым loopback proxy. Изоляция относится только к эфемерному CI. Не выводить «реальный игрок» из одного `build_channel:release`.

## Остаточные риски и следующий шаг

1. На физическом устройстве: ощутимость/баланс вибраций и звука, live banner/rewarded/interstitial без VPN, реальная выдача/закрытие рекламы, фоновые уведомления с ограничениями производителя, RuStore review flow.
2. В кабинете AppMetrica: приём schema 2, правильный package/counter/build, исключение QA-сборок; контрольная VK-установка и постбеки. Bridge подтверждает локальный SDK enqueue, не сервер. Возможен crash gap между enqueue и сохранением receipt: дедупликация по `event_id` обязательна.
3. Историческая причина трёх `save_error` не установлена. Исправлен конкретный ложный путь и добавлена диагностика; это не доказательство устранения всех дисковых ошибок. Прерывание реального дискового commit/обесточивание здесь полностью не воспроизводились; неподтверждённые записи при убийстве процесса гарантировать нельзя. Предупреждение и повтор сохраняются.
4. 5–8 новых игроков должны пройти первые 10–15 минут с наблюдением. Проверить понимание правила, заметность короткого маршрута, первую самостоятельную пару, ценность банки/медали/страницы, добровольность рекламы и естественную точку остановки. Автоматические решения этого не устанавливают.
5. Интересность всех 2400 задач и рост retention не доказаны. В аудите — измеримые гипотезы; Director, скрытая DDA, новые валюты и ML не добавлялись.

Проверки старого payload на предыдущем кандидате, wire v5/meta v2 и повторных наград в текущих моделях/браузере прошли в доступной среде. Downgrade не обещается. Live-рекламные ID, частоты и фундаментальные правила не менялись. Перед магазинной выдачей нужен отдельный подписанный артефакт с проверкой production-сертификата; unsigned CI APK предназначен для технической приёмки.
